# 毫米波雷达校验和核实记录

## 1. 核实方法

从 `doc/毫米波雷达通信协议231101_V1.docx`（v0.1，2023/11/1）中提取正文与表格，
逐条比对 `src/inno_device_radar_node.cpp` 的 `FrameParser` 实现，同时与 ROS1 原实现
（`inno_double_wedge_driver_ws-master/src/double_wedge_driver/src/inno_device_radar_node.cpp`）
交叉核对。

## 2. 协议原文（雷达信息帧 ID 0x01）

| 字节号 | 含义 | 备注 |
|---|---|---|
| 0~1 | 帧头 | 0xaa 0x55 |
| 2 | 帧ID | 用于区分不同消息 |
| 3~4 | 数据包长度 | 长度表示从数据包长度字段开始到校验位之前（n-3） |
| 5 | 固件版本号 | |
| 6~7 | 雷达状态 | 可定义雷达状态码 |
| 8~9 | 测量目标总数 | |
| 10~13 | 目标1距离 | 4字节浮点数表示 |
| 14 | 目标1信强 | 信强值=dB数 |
| 15~n-1 | 其他目标信息 | |
| n | 奇偶校验 | 累加和校验占1字节 |

## 3. 核实结论

### 3.1 协议**已**明确的内容

- 校验方式为**累加和**，占 1 字节，位于帧尾字节 n。
- 长度字段的覆盖范围：从字节 3（长度字段自身起始）到校验位之前，数值为 `n-3`。

### 3.2 协议**未**明确的内容

**协议没有写明累加和的起止字节。**

需要强调：「长度从长度字段开始」是对**长度字段**的定义，**不等于**同时定义了
校验和的累加范围。两者是独立的定义，协议文档只给出了前者。

当前实现假定二者范围一致（即累加范围 = 长度字段所覆盖的范围），这是一个
**合理但未经文档证实**的推断。

## 4. 当前实现

`src/inno_device_radar_node.cpp` `FrameParser::checksum`：

```cpp
static std::uint8_t checksum(const std::vector<std::uint8_t> &bytes, std::uint16_t length)
{
  std::uint8_t sum = 0;
  for (std::size_t i = 3; i < static_cast<std::size_t>(length) + 3U; ++i) {
    sum = static_cast<std::uint8_t>(sum + bytes[i]);
  }
  return sum;
}
```

累加范围为 `bytes[3] .. bytes[length+2]`，即从长度字段高字节开始，到校验位前一字节结束。

### 4.1 与 ROS1 原实现的一致性 —— 已核对，行为一致

ROS1 原实现（`Interface_handler_Type_def::checksum`）：

```cpp
uint8_t Interface_handler_Type_def::checksum(uint8_t *data, uint8_t len) {
  uint8_t i = 0;
  uint8_t sum_check = data[0];
  while (i < len - 1) { sum_check += data[i + 1]; i++; }
  return sum_check;
}
```

调用点：`sumcheck_cal = checksum(&data_content[3], length);`

即从 `data_content[3]` 起累加 `length` 个字节，范围为 `data_content[3] .. data_content[length+2]`。

**两者累加范围完全一致。** ROS2 版本只是把指针传参改为按索引访问，未改变算法语义。

ROS1 的另一处实现 `ByteStream::verifyChecksum`（`for i = 3; i < length - 1`）在原工程中
**从未被调用**，属于死代码，不作为行为依据。

## 5. 处理决定

**保留当前算法，本次不做任何修改。**

依据本任务约束：协议未明确校验起止字节时不得凭猜测修改。当前算法同时满足
「与 ROS1 既有行为一致」和「与协议已明确部分不矛盾」两个条件，没有修改的依据。

同样**未修改**：字节序（大端，与协议"网络字节顺序"一致）、帧长度定义、目标解析逻辑。

## 6. 待验证事项

以下需通过厂家说明或已知有效原始帧确认：

- [ ] 累加和的准确起止字节。重点确认是否包含帧头 `0xaa 0x55`（当前实现**不包含**）。
- [ ] 目标距离字段的实际类型。协议表格写"4字节**浮点数**表示"，但 ROS1 与 ROS2
      实现均按 `uint32` 读取后乘 `0.001` 当作毫米处理
      （`inno_device_radar_node.cpp:318,323`）。**协议文字与实现存在分歧**，
      需实帧确认。本次未改动，因为按 IEEE-754 解释会彻底改变数值语义，
      属于协议解析数学逻辑，无实据不得擅改。
- [ ] 状态码宽度。协议"雷达状态码说明"表列出单字节值（0x08 正常 / 0x02 时钟异常 /
      0x04 电源异常），而帧结构表中字节 6~7 为双字节雷达状态，实现按 `uint16` 读取
      并与 `0x0808` 比较判正常（`:344`）。双字节与单字节状态码的对应关系需确认。

### 6.1 建议的验证方式

在 Jetson 实机连接毫米波后：

```bash
ros2 launch double_wedge_driver start_radar.launch.py serial_port:=/dev/ttyXXX
# 观察节点日志中的 "Radar frame checksum errors" 计数
```

若校验错误计数持续为 0 且目标数据合理，可反证当前累加范围正确；
若计数持续增长，则需抓取原始字节流逐帧人工核算后再定位。

## 3. 迁移中修正的边界问题

**必须明确：本次迁移并非"只替换 ROS API、协议逻辑完全没动"。**
以下修正改变了原 ROS1 的实际行为，均已对照 ROS1 原码核实：

| 修正项 | ROS1 原行为 | ROS2 现行为 |
|---|---|---|
| UDP 有效长度 | `handle_receive` 显式丢弃 `bytes_transferred`（原码第 598 行签名注释掉该参数），改用 `packet.size()`，即 1500 字节缓冲区全长 | 使用实际 `bytes_transferred`，不再把缓冲区旧数据当作当前包 |
| 毫米波帧边界 | 按 `length + 3` 索引解析 | 解析为 `payload_length + 4` 的完整帧，目标数超出有效载荷时截断并告警 |
| 未初始化读取 | `frame_handler` 中 `frame.packet_length` 从未赋值即参与边界比较 | 改用已解析的 `payload_length`，消除未初始化读取 |
| 时间戳毫秒 | 未同步分支 `timestamp = s_time + ms_time`，漏乘 `0.001`（原码第 412 行） | `timestamp = seconds + milliseconds * 0.001` |
| UDP 端口 | socket 构造时硬编码绑定 2368 | 改为运行时 ROS2 参数，构造后再 bind |
| 串口设备 | launch 默认 `/dev/ttyS9` | 改为参数，默认 `/dev/ttyUSB0` |

**其余协议行为未做逐项等价性验证。** 上表只覆盖已识别并主动修改的部分，
不等于已确认 ROS2 与 ROS1 在所有输入下行为一致。

毫米波 `blind_area` 和 `hight_air_mode` 已作为 ROS2 参数暴露并记录；
原 ROS1 中对应的协议下发代码本身处于注释状态，因此迁移没有擅自启用未经实机验证的配置帧。

## 7. 未决事项

- 点云接口与坐标系：见 `点云接口与坐标系现状.md`。
  **2026-09-07 回放实测确认 frame_id 分裂**：
  `/lidar_data`、`/livox_data` 为 `lidar_frame`（驱动节点默认值），
  `/inno_lidar_cloud` 为 `lidar_link`（`test_lidar_driver.cpp:33` 默认值），
  **两者之间没有任何 TF 变换发布**。下游按 frame 查 TF 会失败。
  这证实了 W00-C 提案 2 的必要性，建议尽快冻结 ADR-001。
  `map` 未在实测中出现。
- **[新问题] PointCloud2 时间戳为设备相对时间**：实测 `header.stamp.sec = 46`
  （即 1970-01-01 00:00:46），非 Unix epoch。
  根因见 `inno_device_lidar_node.cpp:298-311` 未同步分支——
  抓包时雷达未授时（0/119990 包置同步位），时间戳字段是设备上电后的相对秒数。
  现有防护 `timestamp > uint32::max()` 只挡上界，46 秒能通过。
  **影响 MapMOS、TF、多传感器同步、rosbag 对齐。**
  待裁决：保持原样要求现场授时 / 未同步时回退系统时间 / 双字段。
  **接真实雷达并授时后行为可能不同，不要仅凭回放下结论。**
- **[口径冲突] 有效回波率**：W00-C §9.3 记 0.909%（源自 `manifest.json` 统计），
  本轮实测 `na70_capture_20260826_175334` 前 2000 包非零距离点占 **47.913%**。
  两者相差约 50 倍，明显口径不同（可能是「有效目标点」vs「非零距离点」）。
  **DBSCAN / `min_cluster_points` 等下游参数设计前必须先统一口径。**
- 毫米波校验和：见 `毫米波校验和核实.md`。协议未明确累加起止字节，保留现算法待验证。
- 毫米波目标距离字段类型：协议写"4字节浮点数"，实现按 `uint32` 处理，存在分歧，待实帧确认。
- **话题名实测**：`/lidar_data`、`/livox_data`、`/livox_status`、`/inno_lidar_cloud`。
  状态话题实名为 `/livox_status`（非文档部分位置写的 `/lidar_status`）。
- **NA70 真实网络参数**（抓包实测）：`192.168.1.66:7000` → `192.168.1.129:2368`，
  雷达 MAC `00:0a:35:01:fe:c0`，UDP 载荷 1410 字节，1000 包/秒，
  网口 `enP8p1s0`（100 Mb/s **半双工**）。
  `1410 = 200 点 × 7 字节 + 8 字节时间戳 + 2 字节工厂位`，与驱动常量精确吻合。
- **Jetson `rosdep` 未初始化**（`sudo rosdep init` 未执行）。本次绕过方式为逐项 `dpkg -l`
  核对依赖后直接 `colcon build`，已全部命中。若后续新增依赖，需要用户执行
  `sudo rosdep init && rosdep update`。
- **Jetson 环境污染**：`colcon list` 会触发 `radar_mapmos` venv 的
  NumPy 1.x/2.2.6 ABI 冲突并中断（torch 编译于 NumPy 1.x）。
  不影响 `colcon build` 和节点运行，但排查时需注意；建议后续隔离该 venv。

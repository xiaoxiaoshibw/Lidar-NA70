日期：2026-09-21（2026-09-23 更新）

## 1. 路线决策

用户于 2026-09-21 明确将近期优先目标恢复为：**先把足球门识别成功，用足球门验证从原始点云、预处理、检测、评价到跟踪和 WebUI 的完整感知链。**

本计划是当前唯一执行入口。细线 W1 已完成工具开发，但真实回波归属仍 `NOT_EVALUATED`，现暂停为保留分支；固定点转台和历史无 IMU 移动建图继续保留，不进入足球门开发顺序。

开发顺序固定为：

```text
G0 可信真实标注与静止窗口
  → G1 地面和相对高度基准
  → G2 人工 ROI 内含球网几何检测
  → G3 全场候选搜索
  → G4 当前测量驱动的跟踪
  → G5 冻结参数与真实验收
```

该顺序将“搜索区域是否覆盖目标”“局部几何能否识别目标”“跟踪能否稳定关联”分开验收。任何后级输出都不能掩盖前级失败。

## 3. 成功定义

足球门“识别成功”分为四个递进层级：

| 层级 | 成功条件 |
|---|---|
| 局部几何成功 | 在人工 ROI 内，仅依赖点云测得左右边界和上沿；支撑点真实存在，框与标注一致 |
| 全场检测成功 | 不读取目标 ROI 或真值位置，在完整搜索范围内产生正确测量候选，同时控制背景误检 |
| 跟踪成功 | 连续不同原始观测形成同一 ID；缺测、预测、失锁和重获语义正确 |
| 阶段验收成功 | 冻结参数后，在独立真实录制及负样本上达到门禁，所有失败可从 Stage trace 复现 |

只有第四层达到要求，才把 P3 标为 PASS 并进入持久化任务。页面出现框、候选数增加或 TRACKING 帧数增加均不等于成功。

## 4. G0：建立可信真实真值

### 目标

消除当前默认框、帧归属和运动状态不可信的问题，为后续每次修改提供固定评价分母。

### 工作

1. 优先回查旧版本实际锁定的 frame 153 和 frame 597，保存当时测量框、支撑点、执行配置和原始三视图，并与现场照片/独立标注核对。旧锁定证明系统曾找到稳定门形结构，但在复核前不判定为真实足球门。
2. 同时检查主 PCAP 的帧 0–199、64–83、308–327。这些窗口有球门状结构，仅作为候选正窗口，不预先判定为真值。
3. 在原始点三视图中标注：左立边、右立边、上沿、局部地面、网面/斜撑、不可见部件。保存原始 `(frame_index, point_index)` 引用。
4. 将真值观察单位区分为 `single_frame` 和 `accumulated_window`。窗口标注绑定 capture、起止设备时间、实际时长、坐标系和来源 cloud id，不能把一幅累积云的框复制成多个单帧真值。
5. 废止旧默认 7.32 米框的真值资格，原样保留为 `PENDING_REVIEW` 历史证据。宽高未知时写 null 和估计误差，不按算法输出回填。
6. 判断窗口内雷达是否静止。文件名、球门静止或画面看似稳定都不足以证明雷达静止；依据现场记录、静态背景展宽和设备时间给出 `confirmed/unknown/moving`。
7. 建立开发小集：至少 5 个完整可观测正窗口、5 个 reviewed 背景窗口；网面、部分遮挡和稀疏观察单独分层。若现有录制不足，补录固定雷达、固定球门及纯背景，每类至少 3 次、每次连续 30 秒。
8. 已查看过的 `caochangyou` 只能作为开发/回归数据。`caochangzuo`、`caochangyidong` 先核查使用历史；最终验收至少保留一次未用于调参的独立录制。

### 输出和门禁

- 更新 `docs/GOAL_DEBUG_CONTRACT.md`，加入窗口真值、部件支撑、运动状态和标注误差字段。
- 标注工作台保存实际窗口上下文，不允许使用过期云保存到当前帧。
- 评分器分别计算提议覆盖、局部几何、当前测量和跟踪，不把 UNKNOWN 帧当误检或真值。
- 至少 1 个 reviewed 正窗口和 1 个 reviewed 背景窗口完成端到端复算后，才进入 G1；5+5 小集完成后才允许冻结 G2 参数。

主要文件：`docs/GOAL_DEBUG_CONTRACT.md`、`AnnotateApp.tsx`、`demo_api.py`、`score_goal_detection.py`、标注测试。

## 5. G1：统一地面与高度基准

### 目标

所有柱高、上沿高度和框高以可信局部地面为参考；输出仍恢复到原始 `lidar_link` 坐标。

### 工作

1. 明确四个量：`sensor_z`、相对地面高度、实际观测跨度、估计完整结构高度。已被过滤的柱底不能继续参与“观测高度”。
2. 修正当前“只有坡度超过阈值才启用归一化”的语义。平地可有安装高度偏置，低坡度不能自动解释为无需地面基准。
3. 地面模型同时验证点数、XY 覆盖、设计矩阵秩、残差、坡度、来源年龄和窗口运动；低分位点本身不自动等于地面。
4. 地面不足或退化时明确拒绝模型，保留原始点和原因。禁止写死 `z+1.3 m` 等诊断偏移作为生产标定。
5. 候选中心、左右边界、上沿和八角点统一做正逆坐标转换；XY、intensity 和原始引用保持不变。

### 测试和门禁

- SYNTHETIC 覆盖安装高度偏置、低坡度、pitch/roll、共线退化、墙面误拟合、稀疏地面和过期地面模型。
- 已知平面测试中，地面高度误差 P95≤0.10 米。
- reviewed 正窗口中的左右边界不再仅因绝对 z 门限丢失；过滤前后每个部件的点数、跨度和拒绝原因可复算。
- G1 只改高度因素；同一窗口保留旧版对照，不同时修改 BEV 或候选评分。

主要文件：`pipeline.py`、`detector.py`、`geometry.py`、`goal_detection.yaml`、`test_goal_evidence.py`、`test_goal_geometry.py`。

退出证据（2026-09-23）：[G1 退出证据报告](evidence/goal-demo/20260923-g1-exit-evidence/REPORT.md)——合成已知平面 P95≤0.083 m（含噪场景）、reviewed 正窗口逐部件绝对/相对高度保留对照（左立边 97/300 → 300/300）、真实窗口地面模型质量表、恢复一致性用例清单。

## 6. G2：人工 ROI 内识别含球网的真实球门

### 目标

绕过全场 BEV 搜索和 tracker，在人工 ROI 内证明正式几何检测器能从真实点云测得球门结构。这是第一个必须完成的算法里程碑。

### 工作

1. 人工 ROI 只限制输入范围，不向检测器提供真值端点、宽高或朝向。
2. 在地面相对坐标中提取竖直结构，估计球门所在局部立面，再在该立面中分别寻找左边界、右边界和上沿。
3. 球网和斜撑作为独立支持/干扰层，不能再通过三维连通关系把两侧边界合成一根宽柱。
4. 首选有界的鲁棒直线/边界拟合；输出每个部件的原始支撑点、不同来源帧数、残差、覆盖长度、断裂和拒绝原因。
5. 完整球门至少需要两侧竖边证据；上沿缺失时输出部分结构，不能沿默认尺寸补成高置信度完整框。
6. 宽高先验来自 reviewed 实测范围。未获得实测范围前，算法输出测量值和不确定度，不用旧 UI 默认尺寸作强门限。

### 测试和门禁

- 将“1513 点网面组件、RMS 半径约 1.774 米而被判为宽柱”的真实失败转成固定回归。
- SYNTHETIC 增加网面、斜撑、围栏、树干、门形缺口、非标准尺寸、单侧遮挡和上沿缺失。
- 首批 5 个完整正窗口逐个检出；5 个 reviewed 背景窗口不产生高置信度完整球门。失败窗口不能从名单中删除。
- 小集目标：中心误差≤0.5 米、宽高误差≤0.3 米，并且左右边界和上沿分别具有实际支撑。样本太少时报告逐例结果，不宣称总体准确率。
- Inspector 同屏显示原始上下文、参与点、三类部件支撑和测量框；诊断开关不得改变检测结果。

主要文件：`geometry.py`、`detector.py`、`pipeline.py`、`observability.py`、`synthetic.py`、`DemoApp.tsx` 及相关测试。

## 7. G3：恢复全场候选搜索

### 目标

局部几何已经通过后，再让系统在不知道球门位置的情况下找到包含球门的有限搜索区域。

### 工作

1. 分离空间占据和时间重复观测。不得继续把体素代表点数除以窗口帧数解释为真实密度。
2. 新提议器优先使用高度层、竖向边界和有限宽度组合；网面中间不要求为空，两侧边界也不要求先成为孤立 blob。
3. 原始观测次数旧方案只保留为失败对照，不恢复为主线。若使用 distinct-frame occupancy，必须同时报告空间支持，防止同一位置重复观测放大证据。
4. 对单帧、0.5/1/2/5 秒实际设备时间窗及 0.1/0.25/0.5 米体素做同窗比较。时间跳变不拼窗，窗口不足明确标注。
5. 取消固定 demo ROI 的生产限制；保留可解释的物理距离/FOV边界和最大区域预算。

### 测试和门禁

- 固定复现 20 帧“原始14点→体素8点、门限11”和200帧“258点→15点、门限110”的旧失败。
- reviewed 可观测窗口的提议召回目标≥95%；同时报告每窗口无匹配提议数、区域数量、大小、截断率和耗时。
- 每帧最多保留配置预算内的区域，不能用覆盖全场的大框取得高召回。
- 背景窗口分别统计提议率；G3 PASS 只代表找到正确区域，不代表最终球门 precision/recall 已通过。

主要文件：`bev.py`、`accumulation.py`、`pipeline.py`、`observability.py`、`goal_detection.yaml`、`test_goal_bev.py`。

## 8. G4：当前测量驱动的锁定与跟踪

### 目标

将 G2/G3 的真实测量接入现有 tracker，验证确认、跟踪、缺测、失锁和重获。

### 工作

1. 只有 `MEASURED_CURRENT` 能增加确认帧、刷新位置和计入 detection；`PREDICTED_RECENT` 只保持搜索连续性，`EXPIRED_HISTORY` 只作诊断。
2. 相同 observation signature 在连续窗口中不得重复增加确认次数。
3. 使用 `device_time` 计算 dt；时间异常使用明确 fallback，不能默认为稳定 10 Hz。
4. 关联继续使用中心、bearing、宽高、无向 yaw、置信度和预测不确定度的唯一函数；显示分数与选择决策必须一致。
5. 新目标、失锁后新段和重初始化清空旧速度、协方差、miss 计数和轨迹；预测框、最后测量框和 LOST 历史框分开保存。
6. 固定雷达先通过，再测试左右扫描/移动录制。运动窗口发生明显展宽时缩短或拒绝，不恢复无 IMU 点云里程计作为默认补偿。

### 门禁

- 目标完全不可见期间错误当前测量和错误确认均为 0。
- reviewed 连续序列 ID switch=0；首次锁定必须来自配置要求数量的不同当前观测。
- 失锁耗时、重获耗时、最长连续命中和最长缺测按设备时间报告。
- 暂停、seek、配置变更和同帧重复轮询不能制造新测量或延长轨迹。
- 固定数据通过而运动数据失败时，保留 G2/G3 状态并将 G4 标为 FAIL/BLOCKED，不能用静态结果替代运动验收。

主要文件：`tracker.py`、`pipeline.py`、`focus.py`、`demo_api.py`、`DemoApp.tsx`、`test_goal_lock.py`、浏览器测试。

## 9. G5：冻结参数和发布验收

### 数据冻结

- 开发集可使用已经检查过的 `caochangyou` 和 SYNTHETIC seeds 0–19。
- 既有 seeds 1000 等已经看过，只作回归，不再称未见验证。
- 新验证 seeds 2000–2049 在首次运行前写入 manifest；验证结果不能用于继续调同一版本阈值。
- 正式真实验收至少包含 30 个完整正窗口、30 个背景/困难负样本窗口，来自至少两次独立录制；窗口按连续片段分组，至少一次录制完全不用于调参。

### 拟定退出门禁

| 层级 | 标准 |
|---|---|
| 来源与契约 | 点、掩码、部件、候选、框、帧/窗口/config身份100%可复算 |
| 地面 | 已知地面高度误差 P95≤0.10 米；退化输入不输出可信模型 |
| 提议 | reviewed 可观测窗口召回≥95%，满足冻结区域数量/大小预算 |
| 检测 | 完整可观测真实窗口 precision/recall≥95%；中心P95≤0.5米，宽高P95≤0.3米 |
| 跟踪 | ID switch=0；不可见期间错误确认=0；失锁/重获按段报告 |
| 工程 | 后端全量、前端构建、必要Playwright通过；输入/源码/config/标注哈希完整 |

困难场景单列：单柱、缺上沿、球网稀疏、目标出 FOV、运动展宽、时间异常。不得用普通场景平均值掩盖失败。Windows 性能只作开发数据；Jetson Orin Nano/Humble 性能验收属于后续出口。

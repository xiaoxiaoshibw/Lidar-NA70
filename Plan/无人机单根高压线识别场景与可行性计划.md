# 无人机机载 NA70 单根架空导线识别：场景与可行性计划

日期：2026-09-24。状态：**S0 合成场景与扫描方向审计已实施；S1 真实细线回波归属未验证**。本计划响应机载导线识别需求，作为独立候选路线；不把已有足球门 G0–G5 结果或细线 W1 工具烟测解释为导线能力通过。S0 实施结果见 [审计报告](evidence/thin-wire/20260924-s0-release/REPORT.md)。现行主线仍以 `Plan/README.md` 为准，路线切换须在那里记录。

## 1. 任务定义与边界

目标是在无人机前向飞行时，由**机载 NA70** 对前方一根架空导线给出当前测量支撑的告警：可见线段的机体系位置、最近距离、方向、置信/未知状态、最近有效观测时间和输出延迟。第一阶段只做感知与告警评估，不连接飞控或宣称避障安全能力。需要同时报告水平、垂直及三维最近距离；仅有历史轨迹预测时标记为 `PREDICTED`，无当前回波时不能显示为当前检测。

“一根高压线”在合成场景中代表**一根架空导线的几何体**。点云本身未必能区分高压导线、普通电线、拉线或树枝；无法凭几何确认类别时输出 `UNKNOWN_LINE`。真实电力设施的电压等级及线径不能从外观臆定，现场验证优先用可控、无带电风险的替代细线，再依合法现场条件采集真实导线。

## 2. 已知输入与当前证据

| 项目 | 当前事实 | 对本任务的含义 |
|---|---|---|
| NA70 协议 | 正式驱动/解码器使用 1410 字节包、每包 200 个点、100 有效包聚成一帧；距离码单位 16 mm，俯仰/方位码单位 0.0258°/0.0432° | 使用正式解码与原始射线码；**码值步长不是光斑大小、实际角分辨率或细线检出保证** |
| 现有时序 | 约 10 Hz 的 100 包帧不是一次完整重复扫描，单帧可能漏过细线 | 按包设备时间做因果窗口，统计实际照射覆盖；刷新率与新测量率分开 |
| 细线 W1 | 原始审计工具、配置、来源追踪已就绪；现有真实 PCAP 没有已复核细线位置与配对背景，回波归属 `NOT_EVALUATED` | 先证明真实线的回波，不能从 ROI 内有点直接推断导线检出 |
| 运动与部署 | 当前移动球门数据的无 IMU 运动校准未过门禁；Windows PCAP/WebUI 是本地开发环境，Jetson Orin Nano/Humble 是最终性能目标 | 运动积累必须有可信位姿与时间同步；Windows/WSL2 结果不能替代 Jetson 实测 |
| S0 实施 | 场景生成、三视图、真实角码几何覆盖和无导线对照已运行 | 仅证明工具/场景可复查；60° 安装角为合成假设，实际外参与真实导线回波仍待 S1 |

源码依据：`ROS2/src/double_wedge_driver/src/inno_device_lidar_node.cpp`、`web/backend/decoder.py`；细线证据入口：`Plan/细线回波验证与逐级开发计划.md`、`Plan/evidence/thin-wire/20260921-w1-development/REPORT.md`。NA70 在导线材料、线径、角度、距离及天气下的有效探测范围尚无本项目实测结论。

一个仅用于设计敏感性分析的角宽估算：直径 20 mm 的细线在 20/50/100 m 处约为 0.057°/0.023°/0.011°。这是几何视角，并不等于回波概率；扫描轨迹、光束发散、入射角、反射率、背景和距离共同决定是否得到有效测距。该直径也只是合成参数，**不代表目标实物已测线径**。

公开研究说明具备相应传感器与数据条件时可从无人机 LiDAR 提取导线；例如 [Chen 等的流式识别研究](https://www.sciencedirect.com/science/article/pii/S1569843222001558)和 [Shen 等的束导线分割研究](https://www.sciencedirect.com/science/article/abs/pii/S0263224123001677)。这些系统与 NA70 不同，其准确率、频率和距离均不能移植到本项目。厂商 [Livox Avia 参数页](https://www.livoxtech.com/avia)专门强调光斑、回波模式和线缆应用，反证本项目必须单独核实 NA70 的相关硬件条件；不能据别的雷达规格推断 NA70 性能。

## 3. 已构建的户外场景定义

机器可读定义见 [场景清单](../tools/scenarios/uav_single_wire_outdoor_v1.json)，[俯视和正视概念图](evidence/thin-wire/20260924-synthetic-scene/scene.svg)展示其空间关系。坐标为右手世界系，地面 `z=0`、`+x` 为无人机名义前进方向、`+z` 向上，单位米。几何与轨迹全为 `SYNTHETIC` 真值，不写成 NA70 回波、真实 PCAP 或物理级传感器仿真。

| 元素 | 初版几何 | 用途 |
|---|---|---|
| 地面与背景 | 60×60 m 地面、两端支撑杆、单棵树与短围栏 | 接近操场/户外背景；包含遮挡与误检来源 |
| 单根导线 | 位于约 `x=35 m`，端点 `y=±25 m, z=19 m`，中点下垂 1.5 m；示例直径 20 mm | 独立真值线段，允许分段可见与下垂拟合 |
| 无人机/雷达 | 无人机从 `(0,0,12)` 沿 `+x` 移至 `(22,0,12)`；雷达安装外参作为待标定输入 | 测前向接近、姿态扰动与线到机体的最近距离 |
| 困难反例 | 树枝、围栏横杆、支撑杆；可切换无导线、稀疏回波、局部遮挡、时间跳变 | 检验 `UNKNOWN_LINE`、误报及缺测处理 |

场景分三层实施，且每层保留自己的标签和真值：

1. **几何展示层**：根据清单渲染地面、支撑、导线、无人机路线，显示独立的真实距离；用于评审空间关系，不能产生“检测成功”指标。
2. **射线覆盖层**：从正式解码器导出一段真实 NA70 的原始角码和包设备时间，仅借用扫描方向/时序，按机载位姿与场景几何计算“可能照射到导线”的射线。`1.pcap` 可用于模式开发，但不作为导线正例。输出命中机会、角度覆盖、目标尺寸和时间窗，不把几何相交自动写成有效回波。
3. **测距观测层**：仅在 W1/W2 取得真实细线目标与背景对照后，依据距离、入射角、线径、遮挡等分层校准有效/无效返回与误差；在此之前只能用明确标为 `ASSUMED_SYNTHETIC` 的多组概率做算法压力测试，不能给 NA70 可行性定量结论。

静态几何和射线层先用 20/50/100 m 等不同初始间距、线径/方向和小幅姿态扰动生成组别。机载运动版本要采用逐包可用时间与实测机体姿态；若只有帧级时间，则保留畸变/不确定性，不声称逐点补偿。任何场景真值都不得传入检测器。

## 4. 可行性结论与停止条件

| 能力 | 当前判断 | 进入下一步的必要证据 |
|---|---|---|
| 合成户外场景与可视化 | **可行**，可直接按清单实现 | 几何、路线、标签可重复；渲染与真值坐标一致 |
| NA70 静止识别替代细线 | **未证明** | W1 独立位置、同机位移除目标背景和重复 PCAP 确认真实回波；W2 给出实际距离/时窗范围 |
| NA70 识别真实单根架空导线 | **未证明，硬件可观测性是首要风险** | 对真实目标或有充分等效依据的替代物，量化线径、材料、朝向、距离、背景、天气与漏检；仅线形不能证明电压类别 |
| 无人机运动时稳定识别 | **未证明** | 位姿/时间同步与外参可靠；运动和静止对照中当前回波支撑、误报及距离误差达标 |
| 实时告警/避障 | **未证明** | Jetson 实测端到端首次发现/重获时间、p95/p99 延迟、观测年龄、丢帧和速度对应提前距离；飞控闭环另行安全论证 |

若在已确认实际扫描覆盖、同机位背景和多次重复采集后，W1 仍无法从原始有效测距中归属细线，则暂停 NA70 单传感器实时识别开发，复核安装/采集条件并评估更合适传感器或多传感器方案。不能用合成点、长时间积累或调低分类阈值越过该停止条件。

## 5. 执行顺序与交付门禁

### S0 场景及扫描审计

- 把清单接入独立场景生成器与 WebUI/离线预览；输出 `scene_manifest.json`、带 `SYNTHETIC` 水印的俯/侧/机载视图、世界与机体系真值、可重复 seed。
- 用真实 NA70 原始角码/设备时间建立“发射方向是否覆盖线”的审计。每组输出每包/每窗几何交会次数、覆盖长度及最大间隙、无效射线比例；把“未照到”和“照到但未测距”分开。
- 验收：相同配置与 seed 重复一致，坐标/外参检查通过，场景关闭导线后真值与交会数为零；几何交会**不计检测 TP**。

### S1 固定雷达真实回波门禁（复用 W1）

- 按现有 W1 现场采集卡，从可测近距开始：固定雷达、独立测量目标端点和线径、3 次目标及 3 次同机位背景录制；每次至少 30 秒。记录安装方向、材料、朝向、天气、固件、原始文件哈希。
- 对原始有效 XYZ/intensity、距离/角码和时间做单帧与因果 0.5/1/2/5 秒窗口对照；不使用球门的距离、高度或体素过滤。
- 验收：重复录制中有与独立位置一致、可与背景区分的真实回波，列出失败窗口；若不满足，保持 `NOT_EVALUATED` 或 `FAIL`，不进入识别性能结论。

### S2 距离和线提取

- 在 S1 已验证条件下按 20/50/100/150/200 m 名义档逐级采集，记录实际距离。先做人工区域线段提取，保存独立支撑包数、线段覆盖率、最大内部断裂、拟合残差与最近距离误差。
- 同时构建树枝、围栏、杆件、其他线结构等负例。开发/验证以录制为单位隔离，冻结 YAML 参数后再评估；结果分层，不以均值掩盖某一朝向或距离的失败。
- 验收：在**实测可观察范围内**，人工 ROI 提取在独立录制上达到预先冻结的召回、误报与几何门限；200 m 是探索档而非默认承诺。

### S3 无 ROI 搜索与短时跟踪

- 全 FOV 提案，先输出 `LINE/UNKNOWN_LINE/NO_CURRENT_MEASUREMENT`；导线身份只在有独立上下文证据时使用。输出每次提案的原始支撑、观测年龄、线段几何、最近距离和来源包。
- 把首次发现、重获、无目标每分钟误报、目标窗口召回、定位误差、最长缺测逐项计量。跟踪 ID 和预测不得补成当前测量。
- 验收：独立真实录制的正例、纯背景及困难负例满足冻结门限，且错报/漏报可逐窗口复查。

### S4 机载运动和实时

- 先台架姿态扰动，再受控低速运动，最后机载。需要机体位姿、雷达外参、时钟对齐和目标/飞行轨迹独立真值；没有足够依据时拒绝融合污染窗口。
- 以飞行速度 `v` 和端到端最坏可用延迟 `T` 计算运动消耗距离 `vT`，把测距误差、姿态误差与安全余量另列；不凭名义传感器距离声称可避障。
- Windows PCAP 正确性 → WSL2/Humble 集成 → Jetson Orin Nano/Humble 实际输入。记录观测等待、解码/算法、队列/传输/显示各段 p50/p95/p99/max、输出新鲜度、峰值内存、丢帧、断流恢复与长跑；预算由任务速度和所需提前距离在验证前冻结。

每门禁保存输入/代码/config 哈希、完整命令、环境、独立真值、逐帧 JSONL、统计和失败案例到 `Plan/evidence/thin-wire/` 下新目录。合成结果始终标 `SYNTHETIC`；真实导线归属只有经复核才标 `REVIEWED_REAL`。

## 6. 当前下一步

先完成 S0 的几何预览和真实扫描方向覆盖审计，同时按 W1 采集卡准备可控替代细线的目标/背景对照。S1 若未通过，不排期“实时导线识别成功”或机载演示指标。完成 S1 后，依据实测距离与观测窗口冻结 S2–S4 的数值门限。

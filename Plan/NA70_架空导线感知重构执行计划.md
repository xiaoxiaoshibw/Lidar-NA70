# NA70 架空导线感知架构重构执行计划（设计稿）

日期：2026-09-25；2026-09-26 更新。状态：`DESIGN_READY / R2_PARTIAL`。WebUI 与 W1 持久化诊断入口已完成第一批实现；R1 公共观测核心迁移、R2 完整 StageTrace/评分契约与 R3 真实回波门禁尚未完成。W1 真实导线回波 `NOT_EVALUATED`，W2–W5 `NOT_RUN`。本计划响应用户提出的架构重设计、开源算法复用、工作区规划与完整可视验收要求。当前[路线索引](README.md)的足球门主线状态和既有失败证据不因本设计稿自动改变。

详细契约：[软件架构](../docs/NA70_WIRE_ARCHITECTURE.md) · [算法设计](../docs/NA70_WIRE_ALGORITHMS.md) · [调试与验收](../docs/NA70_WIRE_DEBUG_ACCEPTANCE.md)。既有[细线 W1–W5 计划](细线回波验证与逐级开发计划.md)和[机载 S0–S4 计划](无人机单根高压线识别场景与可行性计划.md)继续提供物理门禁与应用范围；发生冲突时先更新路线索引和相关契约版本，不静默绕过 W1。

无新 PCAP 的当前执行顺序与已完成对账见[前期开发清单](NA70_无新PCAP前期开发清单.md)。

## 1. 重构目标与取舍

1. NA70 经典 PCAP、Web 回放和后续 ROS2 输入使用单一原始观测契约与唯一协议实现，保留原始距离/角码、强度、包时间、坐标系和帧/包/点身份。
2. 导线算法、运行器、评分器、API 和 UI 分层；固定机位 W1 证据工具不被全视场检测逻辑污染，球门检测器不混入导线几何和阈值。
3. 每个候选可追溯原始点，每个阶段有真实执行 trace，每次回放有不可覆盖的运行包和冻结的真值/配置版本。用户可在工作台直接看到缺点、时间异常、方向未知、拟合失败、覆盖不足和预测状态。
4. 首版优先复用 pyRANSAC-3D 与现有解码/W1 代码；OpenCV 全视场提议和 SciPy 曲线有实验门禁；PCL 为 Jetson 性能不达标时的替换后端。任何替换都走同一独立数据集与评判契约。
5. 正确性、可观测性、稳定性、Jetson 性能依次推进。W1 无真实回波时，停止识别成功与量程结论；硬件/采集条件复核或多传感器路线另行决策。

## 2. 开工基线与工作区

当前工作树含大量修改和未跟踪文件，尤其球门代码和历史证据；实施时先记录 `git status`、live 文件树、相关源码/配置 SHA、输入 PCAP SHA、Python/Node 环境和现有测试结果。不得清理、覆盖或移动不相关文件。若建独立 worktree，它从包含现有 W1/S0 新文件的受控基线开始；从 HEAD 建空白 worktree 会漏掉未跟踪设计与证据。

| 区域 | 预定内容 | 提交/保留规则 |
|---|---|
| `packages/na70_core/` | 纯 Python 观测、时间窗、导线算法、证据/评分契约 | 项目源码，Windows/ROS2 共享；无 Web/ROS2 反向依赖 |
| `web/backend/` | 旧 API 兼容入口、持久化导线任务服务、`/api/wire` | 旧球门/转台 API 定向回归；无第二份算法 |
| `web/frontend/src/wire/` | 独立导线工作台及可复用点云/时间/trace 组件 | 不在球门大组件内继续堆导线状态 |
| `tools/wire/`、`web/tests/wire/` | 回放、评分、证据校验与契约/回归测试 | 输入小夹具可入库，大型 PCAP 不入库 |
| `radar_capture_data/thin-wire/` | 原始有线/无线、距离阶梯和运动 PCAP 及现场测量 | 原始数据不覆盖、不提交 Git，以哈希引用 |
| `web/data/wire/` | 本地会话和标注草稿 | 可重建缓存，不作为正式验收结果 |
| `Plan/evidence/thin-wire/<run-id>/` | 不可覆盖的门禁运行清单、评分、图与失败索引 | 小型复核产物入证据区；大型数据引用原始 SHA |

## 3. 迁移批次与退出条件

| 批次 | 实施范围与复用 | 必须可见的交付 | 退出/回退门禁 |
|---|---|---|---|
| R0 基线与契约 | 固定当前 API、解码、W1/S0 运行身份；完成新 schema 与测试夹具 | 文件/输入哈希、旧测试结果、`wire-truth/run/stage-trace-v1` 契约 | 能复现现有 W1 工具结果；旧状态与失败事实保留 |
| R1 观测核心 | 迁移 `decoder.py` 与 `thin_wire.py` 的协议、时间窗和原始 ID，原路径保持兼容；整合 `wire_scene.py` 重复的角码→方向函数 | 新 `RayBatch`/`ObservationWindow`、逐点/逐包对账报告、时间异常 trace | 正式解码逐点一致、原始 ID 不漂移；失败时切回旧入口 |
| R2 持久化运行与工作台骨架 | 增量 ring buffer、独立限额任务池、manifest/JSONL/NPZ、`/api/wire`、页面 | 无算法也可查看方向未知、有效回波、逐包时间、ROI 和来源点；重启后按 run ID 回看 | 同一 run/window 所有图和指标一致；资源上限/断流/取消有明确状态 |
| R3 W1 真实回波门禁 | 复用 W1 CLI 和配对背景，新增 reviewed 真值录入与双录制对照 | 3 次有线和 3 次同机位无线、每次至少 30 s 的可复核证据，或明确缺失/失败原因 | 只有可归属、可重复的真实回波才进入 W2/W3；缺数据保持 `NOT_EVALUATED` |
| R4 人工 ROI 线段 | 接 pyRANSAC-3D 适配器、有限段与来源/覆盖验证、独立 YAML | 逐候选原始内点、残差、跨度/覆盖/最大缺口、拒绝原因；正负例 A/B | W2 可用距离/时间包络和 W3 冻结门限在独立录制通过；不使用真值端点拟合 |
| R5 全场与评判 | 对照 OpenCV Hough 提议、简单几何/PCA，复用同一三维验证器；完成 reviewed-only scorer | 逐录制 TP/FN/FP、每分钟误报、误差与困难负例索引；点击失败定位首个阻断阶段 | W4 无 ROI，按完整录制分组冻结验证；未复核区域保持 UNKNOWN |
| R6 运动与部署 | 实测外参/同步位姿、测量/预测分桶、ROS2 wrapper 与 Jetson 资源分析 | 首次发现、重获、最长缺测、观测年龄、端到端延迟及内存、长跑和故障恢复 | W5 在 Windows→WSL2/Humble→Jetson 实机逐级验证，未补偿窗口不冒充当前测量 |

R2 可以与 W1 现场采集准备并行推进，但 R4/R5 的真实指标必须等待 R3 的物理门禁。分阶段向共享 `na70_core` 迁移，不一次性替换 `app.py`、`demo_api.py` 和球门 UI；每批次先加契约测试与新入口，后切调用，最后删除已证明冗余的旧逻辑。若阶段回归失败，保留新旧逐点/逐窗差异与失败运行包，再恢复旧入口，不改写旧历史证据。

## 4. 测试矩阵

- **协议/单元**：经典包格式、工厂偏移、安装方向、设备时间、角码/距离零值、空/乱序/NaN/Inf、重复/退化线点、配置非法与容量拒绝。与现有 `web/tests/test_decoder.py`、`test_thin_wire.py` 对账。
- **契约/集成**：Windows CLI、持久化任务、API、UI 对同一 `run_id/window_id` 的原始 ID、StageTrace、候选、真值和评分一致；断流、取消、失败、重启都能回看。球门/转台既有 API 和前端定向回归保持可用。
- **合成压力**：单线、平行/交叉多线、两端孤立点、垂度、遮挡、围栏/树枝、时间跳变、无位姿运动等，所有产物标 `SYNTHETIC`，只验证代码行为。
- **真实冻结验收**：按完整捕获、场景、日期和目标批次隔离开发/验证；先冻结真值与 YAML，再一次性评分。报告 TP/FN/FP、每分钟误报、定位误差、覆盖/缺口和所有失败样本；分母不足时 `NOT_EVALUATED`/null。
- **部署**：WSL2 Ubuntu 22.04/Humble 只验证集成；Jetson Orin Nano/Humble 实际输入记录 p50/p95/p99/max 等待与处理延迟、来源年龄、CPU/GPU/内存、队列积压和长跑。性能预算由飞行速度和所需提前距离在验证前确定。

## 5. 当前第一轮交付定义

第一轮实施仅包括 R0–R2 的可复查平台与 R3 的真实回波准备：形成单一观测契约、不可变运行包和能追溯零距离/方向未知/时间异常/目标背景差异的工作台。第一轮没有 reviewed 导线录制时，真实回波结论保持 `NOT_EVALUATED`。任何源码迁移均遵循[05 开发执行规范](05_开发执行规范.md)，阈值入独立配置，保存命令/环境/哈希/失败项，保留所有无关工作树改动。

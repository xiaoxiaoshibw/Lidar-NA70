## 2. 具体审查发现

以下 P1 表示会直接误导框选、调参或验收，P2 表示开发完整性和可维护性问题；优先级不等于执行阶段编号。

### R01 / P1：Stage 统计没有忠实记录执行链

位置：`web/backend/goal_detection/observability.py:29`、`:75`、`:120`；`pipeline.py`；`accumulation.py`。

`build_observability` 在检测结束后重新计算门限，CLUSTER 直接取已接受候选支撑点，并未记录真实柱提取过程。BOUNDING BOX 用跟踪中心最近候选重新猜选中者；单帧和叠加源还共用同一份 association，不能保证显示的支撑点属于实际关联输入。累积云已经过 ROI/距离/体素化，再称为 RAW 会隐藏早期丢点。除了掩码重算耗时，其他阶段填 0.0，不能解释为真实阶段耗时。

处理：埋点进入实际执行处，区分未执行、输入为空、执行完成、失败；未计时写 null。诊断层只序列化，不再次判断。

### R02 / P1：Raw、Rejected、Supporting 混用且来源不完整

位置：`web/backend/demo_api.py:325`–`:365`、`accumulation.py:_voxel_downsample`。

叠加模式把完整当前单帧全部标为 rejected 后拼接叠加云，其中部分点实际参与运算，灰色含义不真实；RAW 显示当前单帧，而 Inspector 统计叠加云。选中候选时直接改分类为 supporting，可能覆盖阶段拒绝语义。体素仅保留质心，支撑索引无法追到原始 PCAP 帧中的点；拼接后数组偏移也没有独立来源契约。

处理：背景和排除是不同图层；支撑高亮是独立属性，不能改变 active/rejected。发布 cloud_id 和来源映射；UI 同屏统计明确每种云的点数。

### R03 / P1：展示的 Association Score 未参与选择

位置：`web/backend/goal_detection/tracker.py:248`、`:291`、`:337`。

实际选择使用 confidence 减距离惩罚，展示却使用距离/bbox/方向/历史加权分；bearing_similarity 直接复制 distance_similarity。首次候选未统一应用 min_confidence。Kalman 固定 dt=1；SEARCHING 重新获得候选和 LOST 切换新候选时未完整清理旧滤波状态，可能把新框拉向旧位置。重获和尺寸突变也缺少统一几何门控。

处理：输出每条匹配边及拒绝理由，唯一打分函数同时用于选择和展示；使用设备时间；新段清空滤波、速度、计数和轨迹。球门无向柱线的 yaw 比较处理 π 对称。

### R04 / P1：失锁框仍被当作当前检测

位置：`tracker.py:43`、`web/frontend/src/DemoApp.tsx:598` 起。

本轮只读复现：输入 5 帧候选再输入 45 帧空候选，返回 state=LOST、detected=true、confidence=0.95、last_seen_index=4。前端跟随和绘框使用 detected，且无目标时未总是清理 goalRef；每次轮询都追加轨迹，暂停也可能重复记录。完成时清空 sessionId，后续 Snapshot 导出和历史查询失去入口。

处理：分离 has_measurement、confirmed、predicted、lost；失锁保留灰/红色历史框及 last_seen，不计为当帧检测。轨迹从后端按帧读取，断段不连线。

### R05 / P1：旋转框 AABB 与画面定义不一致

位置：`detector.py:49`、`DemoApp.tsx:512`。

_bbox_limits 直接 center±size/2，忽略 yaw；但前端将 local box 旋转 yaw−π/2。例如 yaw=0、size=[0.6,5.4,2.4] 时，世界 X 应沿门宽展开，当前接口却沿 Y 展开。Z 修正后的候选用于跟踪，返回候选列表仍为修正前版本，框偏高无法准确分辨是检测、修正还是滤波造成。

处理：统一 local size、yaw、坐标系及八角点；从旋转角点求 AABB，输出修正前框、测量框和跟踪估计框。

### R06 / P1：评价器会漏掉 UI 保存的框标注

位置：`tools/score_goal_detection.py:96`、`:149`。

score_run 先要求 goal 标注存在 points，导致 UI 保存的 box-only 标注被排除。本轮只读调用 score_run([], [合法 box-only goal])，goal_labels=0。误检判断不限制真值 frame_range，未标注帧可能被判误检，其他时间的标注也可能掩盖误检；主要统计 accumulated_best，未区分最终测量与预测轨迹。

处理：统一 box/点选标注；按 capture、帧、可见性匹配；未标注帧 UNKNOWN，不进入准确率分母。修复后才评估窗口与阈值收益。

### R07 / P1：热更新、seek 与发布快照存在版本竞态

位置：`demo_api.py:93`、`:116`、`:137`、`:419`–`:425`。

处理线程在 control_lock 外执行 process_frame，配置接口可同时替换 self.pipeline/cfg，导致旧帧结果携带新配置版本或窗口信息。state/cloud/debug 分别轮询最新值，前端未验证同一帧和同一配置。已结束任务 PUT 返回成功，但线程已退出，不会完成重算。

处理：任务线程在帧边界消费命令；immutable FrameResult 原子发布；generation/revision 防旧响应覆盖新画面；完成任务以新 run 或明确重算状态响应。

### R08 / P2：全域搜索、拒绝集和性能证据范围不足

默认 demo_roi 固定在 [84,104]×[-36,-17]×[-2,6]，LOST 回到的“全图”仍受该区域限制。单帧和累积链的 ROI 策略也不统一。拒绝候选截断前计算全部柱对的横梁和索引，复杂度可能随杂波急剧增长。候选编号逐帧按排名生成，不是跨帧稳定身份。现有 ROI 可视框还使用前端常量。

处理：显式标记人工先验 ROI，开放全搜索模式并做对照；早期空间门控、有界诊断预算和截断统计；候选 ID 作用域限定到 run/frame/source，Track ID 才承载连续身份；图形参数取自实际执行配置。

### R09 / P2：合成测试和证据不足以证明真实跟踪通过

合成测试使用 window=8、voxel=0.25，与默认 20/0.5 不同；只验证锁过、ID=1和中心步长，误锁静止干扰物也可能通过。缺少真值框误差、遮挡/消失/重入、无球门负样本、近邻相似目标、pitch/roll和时间异常。离线 runner 对多个 PCAP 共用 pipeline，且逐帧记录不含 capture 身份，不能保证多文件隔离。

处理：下述 P2/P6 加入身份与几何指标、默认配置回归、跨文件隔离和完整证据。

## 4. 目标数据契约与算法边界

### 4.1 统一帧结果

每个 FrameResult 必须携带 schema_version、run_id、capture_id、input_sha256、generation、frame_index、device_time、coordinate_frame、config_version、cloud_id。一个版本下的状态、框、阶段和支撑点引用不可变；按该版本查询，不再分别取“最新”后拼装。

原始点身份为 (capture_id, frame_index, point_index)。体素保存到原始点的多对一映射，生产热路径使用紧凑索引，按需展开 JSON。观察坐标系为当前传感器坐标；未补偿的历史叠加必须附时间跨度、来源帧和 compensation=false。

StageTrace 在运算发生处记录：module/function、status、source_cloud_id、input/output/rejected 引用、参数、真实 latency_ms、候选数和 reason_counts。过滤节点满足 input=accepted+rejected；体素降采样等聚合节点单独记录 aggregate_count，不能把合并点误称为拒绝。分支未运行标 skipped，不伪造线性统计。

候选包含 source、ID、父 region/pole ID、accepted/rejected/suppressed、reason、支撑点、局部尺寸、yaw、八角点、AABB、检测分项及 z 修正记录；已选候选 ID 由 tracker 明确返回。全量数据可分页，响应包含 total/returned/truncated。

### 4.2 检测与无 IMU 跟踪路线

Raw → 有效性/距离与可选角域 → 可选人工 ROI → 局部地面/高度证据 → XY 区域提议 → 立柱/横梁/空隙结构验证 → 测量框 → 门控关联 → Track/FOV 更新。界面按实际分支显示，并允许回看 BEV、聚合、Z 修正等辅助节点。

XY 用于提议，不要求完整长方体。全新目标的确认需足够结构证据；横梁缺失降低置信度，已有轨迹可在短时部分立柱可见时维持有限预测，不把缺失部分包装成实测。局部地面估计输出质量和失败理由，质量不足时使用标定/已知安装约束或保持 UNKNOWN，避免凭固定 Z 阈值强行应对俯仰变化。

短时运动模型采用设备时间和预测不确定度；中心、距离、方位、尺寸及无向 yaw 联合门控。距离越远，同样转角造成横向位移越大，因此固定米制门限须在不同距离上评估。确认后 Search ROI 随预测和不确定度变化，漏检逐步扩大；达到超时或不确定度上限转全搜索。

SEARCH → CANDIDATE（合格测量）→ TRACKING（多帧一致确认）；确认事件可保留 LOCKED；短缺测显示预测及年龄，超时 LOST；REACQUIRE 扩大搜索并多帧确认，几何不符的新目标开启新 ID/轨迹段。具体秒数、分数和权重集中 YAML，通过合成开发集冻结。

不将任何雷达运动下的相对轨迹称为球门世界轨迹。独立全局配准不作为本阶段入口；若后续做点云运动补偿实验，复用项目既有配准路线并独立对照，不把未验证变换混入主结果。

## 7. 验收指标及冻结方式

以下数值为下一阶段开发目标，不代表当前已达标。P0 定义指标和输入范围，P2 开发集校准后在验证集首次运行前冻结版本。若目标不适用，必须先写变更理由与新版本，不根据失败结果偷偷放宽。

| 项目 | 拟定门禁 |
|---|---|
| Stage/来源一致性 | 已处理测试帧 100% 通过索引、来源、版本和计数不变量；错误计时零项 |
| 几何契约 | 所有旋转/坐标用例角点、OBB/AABB 与 UI 一致，误差仅浮点容差 |
| Synthetic 常规可观测场景 | 帧级 precision、recall 均≥95%；中心误差 P95≤0.5 m；宽高误差 P95≤0.3 m；ID switches=0 |
| Synthetic 消失/重入 | 无目标专用序列误确认=0；在配置失锁时限内标失锁；可观测重入后≤2 s 重获正确身份 |
| 困难/不可观测场景 | 逐场景报告识别率和失效范围；不得高置信度长期错锁或伪造当帧测量 |
| 真实留出集 | 以新执行计划 R5 为准：已复核完整可观测窗口 precision/recall≥95%、中心 P95≤0.5 m、宽高 P95≤0.3 m，均为待冻结目标；部分/不可见单列，背景与不可见期误报仍计数。旧 recall≥85%/中心≤1 m 提案不再作为可选退出标准 |
| 轨迹评价 | 正确关联比例、ID switches、最长正确连续段、失锁/重获耗时；跟踪正确须先满足真值身份和框误差门限 |
| 本机性能 | 10 Hz 回放稳态处理 P95≤100 ms；回放投递至对应帧显示 P95目标≤200 ms；另报观测积累、首次检出/确认等待，报告 P99/max、超预算比例、积压和冷启动；时钟不可对齐时不直接相减 |
| 资源与控制 | 有界内存/缓存配置；长跑无持续线性增长；暂停/单步/恢复/取消/完成回看/重启恢复全部通过 |

真实 precision/recall 只在审核过的帧区间计算。定位误差必须报告未命中率，避免仅在命中子集报小误差。未补偿 sensor-frame trail 的步长可用于显示连续性，不能当世界速度误差。

# NA70 操场建图：现在该做什么、怎么做

> 2026-09-15 状态变更：用户已选择固定点转台多视角建图。本手册记录的无 IMU 移动雷达 SE(2) 里程计路线转为历史与未来扩展路线，当前不再按下述步骤继续调参。现行执行入口为[固定点转台操场建图计划](固定点转台操场建图计划.md)。

更新日期：2026-09-15  
适用对象：项目负责人、算法开发、前后端开发、测试人员  
当前正式验收依据：[固定点转台操场建图计划](固定点转台操场建图计划.md)；本手册其余内容仅保留为移动建图历史证据。

## 一、先说结论

现在不要直接开发回环、位姿图，也不要继续放宽 ICP 阈值。

当前最先要解决的是：**NA70 的 100 包“帧”不是一次完整、可重复的扫描。** 现有算法把相邻 100 包直接拿去配准，四份新操场数据的正式配准成功帧都是 0。数据中又以远处操场地面为主，近处立柱、扶手等有效结构没有稳定进入雷达视场，因此六自由度位姿不可观测。

正确顺序是：

```text
弄清扫描周期并重新组帧
  → 判断哪些方向真的可观测
  → 先做平面 SE(2) 里程计
  → 建成一张可复查的操场地图
  → 再增加回环、位姿图和重定位
  → 最后接实时雷达并上 Jetson 验收
```

这里的 `SE(2)` 指只估计雷达在水平面上的 x、y 和航向角。雷达需要保持水平、安装高度固定。只有数据证明六个自由度都有足够约束后，才升级到 `SE(3)`。

## 三、现在立即开展的工作

### 第一步：建立正确的 Sweep，不再把固定 100 包当完整扫描

本步骤已于 2026-09-14 完成并通过 G1。实现与四份真实 PCAP 证据见 `evidence/mapping-repair/20260914-sweeps/`。固定 100 包接口仅为 WebUI 向后兼容保留，不再作为里程计算法扫描单位。

#### 要做什么

1. 从 PCAP 中保留每个 UDP 包的：
   - capture time；
   - device time；
   - 200 个点的原始索引；
   - 俯仰码、航向码、距离和强度；
   - 包级时间异常。
2. 分析双楔镜俯仰码和航向码何时完成一次有效覆盖。
3. 按“角域覆盖率 + 最大时间窗 + 最小点数”生成 sweep，而不是每 100 包强行切一帧。
4. 给每个 sweep 输出诊断信息：
   - 开始和结束时间；
   - 包数、点数；
   - 俯仰/航向覆盖范围；
   - 与上一个 sweep 的重复射线比例；
   - 0.3 m、0.6 m、1.0 m 内的对应覆盖率；
   - 是否存在空洞、时间回退或不完整覆盖。
5. 离线 PCAP 和以后实时 UDP 必须调用同一个 sweep 组装器。

#### 建议放在哪里

- 保留 [decoder.py](../web/backend/decoder.py) 作为正式协议解码入口。
- 新建独立的 `web/backend/sweeps.py`，不要把扫描周期逻辑散落在 API 或 WebUI 中。
- 新建 `web/tests/test_sweeps.py`，覆盖完整周期、文件结尾残帧、时间回退、空包和离线/流式一致性。
- 新建 `tools/analyze_sweep_coverage.py`，对四份真实 PCAP 输出结构化 JSON，不把分析脚本变成第二套生产算法。

#### 做到什么算完成

- 中心静止数据的相邻 sweep 能稳定看到同一批射线/表面。
- 使用合理的小距离门限就能得到稳定对应，不需要把对应距离放大到数米。
- 同一 PCAP 一次性读取和模拟实时逐包输入得到完全相同的 sweep 边界。
- 右侧数据的设备时间回退被明确标记和处理，不传播错误速度。

如果这一步做不到，停止后续里程计开发，继续查扫描周期、时间和坐标转换。

### 第二步：把“是否可配准”拆成每个自由度的可观测性

当前 `is_planar` 只给一个整体的“平面退化”结论，不足以指导操场场景。

2026-09-14 状态：算法与合成回归已完成，真实门禁未通过。候选已显式剔除地面主导并使用多尺度 GICP/NDT。四份数据各抽 12 对时左转候选 yaw 为正、右转为负，但左 243 对/右 230 对全量相邻复跑的正式接受数仅 0/3，候选符号一致率接近随机；扩大到 10 个 sweep 跨度仍无改善。不得进入第三步生产融合，先按第四节重新采集连续、可量取、持续包含立柱/扶手/顶棚边缘且带动作时间标记的路线。逐对证据见 `evidence/mapping-repair/20260914-se2*/`。

#### 要做什么

1. 从每个 sweep 中区分：
   - 地面；
   - 立柱、建筑立面等垂直结构；
   - 扶手、围栏、球门等细长结构；
   - 树木、行人等不稳定点。
2. 计算配准 Hessian/信息矩阵的特征值，分别报告 x、y、z、roll、pitch、yaw 的可观测程度。
3. 实现受约束 `SE(2)` 配准：只解 x、y、yaw；高度、横滚、俯仰来自安装标定。
4. 比较当前 ICP、多尺度 robust GICP 和 NDT。所有候选使用同一输入和统一质量指标。
5. 地面可以约束姿态和高度，但不能让大量地面点淹没少量立柱、围栏和球门点。
6. 只有强度跨 sweep 重复性通过统计后，才尝试强度辅助定位。

#### 做到什么算完成

- 中心静止数据不会产生虚假的水平平移和航向旋转。
- 数据只能约束部分自由度时，系统明确显示“哪些方向不可观测”，而不是输出一条看似正常的假轨迹。
- 左右旋转数据的航向变化连续、方向正确，不发生随机跳转。

如果 x、y、yaw 在移动段仍持续不可观测，应调整采集方向，让立柱、扶手或顶棚边缘进入视场；不能继续靠放宽阈值解决。

### 第三步：完成离线 SE(2) 点云里程计

#### 要做什么

1. 使用运动预测提供初值。
2. 使用最近已接受 sweep 构建有界局部子地图。
3. 使用多分辨率配准和稳健核抑制错误对应及树叶等动态干扰。
4. 质量失败的 sweep 不融合。
5. 连续失败后进入 `tracking_lost`；只有通过历史子地图几何验证才能恢复，否则开启新坐标段。
6. 在移动数据上逐段输出：
   - 正式配准覆盖率；
   - 首次失锁时间；
   - 最长连续跟踪时间；
   - 每步平移和转角；
   - 轨迹总长；
   - 每个自由度的可观测性；
   - 地图重影和双层候选。

#### 做到什么算完成

- 移动主区间存在连续正式配准，不再是大部分时间失锁。
- 轨迹方向与实际移动方向一致。
- 静止时不会持续漂移。
- 如果路线回到起点，能够计算首尾误差。
- 没有现场路线真值时，只写“开发验证”，不写“定位精度达标”。

## 四、里程计稳定后怎么建操场地图

不要直接把左、中、右三个文件拼接。正确做法是使用一条连续、有重叠、有回访的轨迹：

```text
中心静止 20 秒
  → 缓慢转到左侧
  → 回到中心
  → 缓慢转到右侧
  → 回到中心
  → 沿看台边缘缓慢平移
  → 回到起点和初始朝向
  → 静止 20 秒
```

采集时：

- 雷达保持水平、高度固定，最好安装在滑轨、小车或刚性支架上；
- 不要始终只朝向操场地面；让看台立柱、楼梯扶手、顶棚边缘持续占据部分视场；
- 在地面标记起点、终点和转弯点，记录各段距离与大致角度；
- 记录文件内开始移动、停顿、返回中心、返回起点的时间；
- 另录一条不参与调参的重复路线，作为独立验收集。

地图至少分为：关键帧原始点、局部地图、优化后全局地图、地面层、稳定结构层和不稳定点掩码。使用照片中的立柱、扶手、球门、围栏和建筑立面建立 ROI，但实际距离要现场测量，不能从未标定照片中估算。

## 五、什么时候才开始完整 SLAM

只有离线里程计通过后，按以下顺序开发：

1. 从历史子地图中检索回环候选；
2. 使用独立几何配准验证候选；
3. 只把验证通过的回环加入位姿图；
4. 执行 `SE(2)` 位姿图优化；
5. 按优化后位姿重新构建全局地图；
6. 实现失锁后的历史地图重定位；
7. 保存所有被接受和被拒绝的回环证据。

至少完成一次真实闭环路线，且优化后首尾误差、固定结构双层和地图重影明显优于优化前，页面才能写“SLAM”。此前统一写“点云里程计与地图融合”。

## 六、什么时候接实时雷达

完整顺序是：

1. PCAP 离线尽快运行；
2. 按原时间戳 1× 实时回放；
3. ROS2/UDP 真雷达流；
4. Jetson Orin Nano 最终性能和长测。

PCAP 1× 回放需要检查每个 sweep 的处理时间、队列深度和是否积压。真雷达测试还要覆盖断流、乱序、设备时间回退、队列满、失锁和恢复。

本机负责数据解析、代码开发、离线验证和结果检查。最终运行、性能与资源验收放在 Jetson Orin Nano/Humble 上；WSL2 结果只能作为集成预验证。

## 九、明确禁止的做法

- 不把固定 100 包继续当作已证明正确的完整扫描。
- 不把左、中、右三份数据按文件名直接拼接。
- 不用数米级对应距离制造高 overlap。
- 不融合质量失败或失锁后的点云。
- 不把照片当作标定后的几何真值。
- 不把 PCAP 回放称为真雷达实时验收。
- 没有回环和全局优化时，不称为完整 SLAM。
- 当前场景不可观测时，不用软件输出冒充真实位姿。

一句话概括：**先把 NA70 的扫描正确组出来，再判断能不能定位；先做可验证的 SE(2) 里程计，再做地图和完整 SLAM。**

## 3. R0：建立可信的真实窗口与评价基础

### 工作

1. 固定当前代码、配置和主 PCAP 哈希，复用现有失败基线，不重新包装旧结果为新通过证据。
2. 优先复核 `you` 的帧 0–199、64–83、308–327；它们是已观察到结构的诊断窗口，不预设为合格正样本。帧 576–595、631–650、1104–1123 用于背景/运动对照，也不自动标为负样本。
3. 从原始点三视图标出左/右边界、上沿、局部地面、可见支架或网面，并记录哪些部件不可见。保留原始 `(frame_index, point_index)` 引用。现场尺寸未知时保存 null/估计误差，不用默认尺寸补全。
4. 真值增加明确的观察单位：`single_frame` 或 `accumulated_window`。窗口真值绑定 capture、起止帧、device_time、体素/范围、坐标系、cloud_id；不能把一幅 200 帧云的框复制成 200 个单帧命中目标。先在 `docs/GOAL_DEBUG_CONTRACT.md` 设计并版本化，再实现读写与评分兼容。
5. 标注状态分为 reviewed、PENDING_REVIEW；可见性分完整/部分/不可见/不确定。只有独立复核过、满足该项评价所需部件条件的样本才进入对应分母；排除项数量与原因全部报告，分母在试验前冻结。
6. 已查看过的 `you` 数据归开发/回归集。`zuo`、`yidong` 核查已有使用情况后作交叉回归；未经查看的独立录制才能作为最终留出集。相邻重叠窗口按连续片段分组，开发与验证之间不得共享原始帧；以最大窗口长度检查隔离，不能随机拆帧造成泄漏。每个独立窗口实验重置累积和跟踪状态；完整序列回放则保留预热范围及其所属数据分组，禁止跨分组继承历史。
7. 首轮优先雷达与目标均静止的片段。`you/zuo/yidong` 文件名及球门本身静止都不能证明雷达静止；记录现场动作依据、窗口内静态背景变化与结构展宽。无法确认时标记 `motion_status=unknown`，只能作运动未知诊断，不纳入静止性能结论。现有片段不足时，补录固定安装、固定朝向的目标和背景，每种条件至少 3 次独立录制、每次连续驻留至少 30 秒；记录实测距离、安装高度/俯仰、尺寸及其误差、遮挡、传感器设置和原始 PCAP。

### 首轮观测与预处理对照

以下是 R0–R3 共用的实验设计，未实现的工具能力在第 9 节列出，不能把规划字段当作现有接口。

| 对照轴 | 首轮设置 | 必须记录 |
|---|---|---|
| 时间 | 单帧，以及 0.5、1、2、5 秒因果累积；200 帧仅复现旧诊断 | 起止设备时间、实际跨度、帧数、丢包/时间质量、部件首次可见时刻 |
| 原始依据 | 正式解码后的有效 XYZ/intensity 与原始引用；保留 PCAP 和无效回波计数 | 过滤前点数、每侧/上沿支撑、独立来源帧数；不将无效距离补成点 |
| 过滤 | 同窗同 ROI 对照距离、绝对高度、可信地面相对高度各自保留/排除的点 | 按实际执行顺序输出原因及部件损失；诊断 ROI 外点计数也保存 |
| 降采样 | 同窗比较不降采样、0.1、0.25、0.5 米体素 | 代表点数、原始来源数、边界跨度/残差与部件保留情况 |
| 检测层 | BEV 提议、绕过 BEV 的局部正式几何、完整管线分别评价 | 提议覆盖、几何误差、测量新鲜度；不得只报告最终框数 |

时间窗以设备时间确定，约 10 Hz 的 5/10/20/50 帧只作数量参考；100 包成帧不代表完成一轮重复扫描。所有窗只使用结束时刻及以前的数据；不跨时间跳变拼窗，开头不足时长标 `partial_window`，不冒充完整 5 秒窗。当前脚本按帧数取窗，第一轮须补实际时间选择与跨度记录后才能报告按秒对照。

先在一个已复核正窗口及一个背景窗口核通全链，再扩展固定的小集。R1 只改变高度相关因素，R2 只改变提议统计，R3 再改变结构提取；每轮保留相同输入/窗口的旧版对照，避免同时修改多个因素后无法归因。实际变体与预算写入实验 YAML 并留存，不将诊断偏移或无过滤模式变成生产默认。

### 首批交付与门禁

- 先建立至少 5 个 reviewed 完整可观测正窗口和 5 个 reviewed 背景窗口；另外列出网面、稀疏/部分观测分层。部分结构不补足完整结构名额，不足时如实记缺口，不自动扩增重复窗口充数。同一片段的多个时长/体素变体只算一组样本。该小集仅作 M1 冒烟验证。
- 首个交付是“同一原始窗口、同一坐标、同一标注”的可复查包。图中测量框必须与保存的点引用相符；旧 0/11 单列为历史比较。
- 缺独立实测尺寸不阻塞代码/原始点诊断；缺复核真值则正式准确率保持 NOT_EVALUATED。需要新采集时，先写出具体距离、姿态、驻留时间、目标/背景清单，再请求用户提供数据。

## 4. R1：高度与地面基准修复

### 工作

1. 明确区分 `sensor_z`、相对局部地面的高度、观测柱身跨度、估计完整柱高；已删除的柱底不得仍参与“实际观测高度”计算。
2. 在充分地面支撑时采用地面相对高度。低坡度不等于零安装高度：检查当前仅按 slope 激活的逻辑，避免平地存在高度偏置却不归一化。
3. 地面模型同时验证空间覆盖、设计矩阵秩/退化、坡度、残差和来源时效。低分位本身不证明地面；墙面、网面、几乎共线的地面点不能因残差小而被接受。
4. 点不足或模型不可信时输出明确状态。若要用已有地面模型，必须有兼容姿态、来源年龄与失效条件；无证据时保留原始点供诊断，不静默套固定 z 偏移。
5. 对倾斜地面的 z 归一化，说明它是局部高度表示，非完整姿态校正。候选、部件点与角点恢复到原始 sensor 坐标，必要时保存变换/近似误差，避免只修框中心导致角点漂浮。

### 测试与门禁

- SYNTHETIC 覆盖安装高度偏置、低坡度、pitch/roll、噪声、共线退化、错误平面、地面稀疏及过期模型。高度范围从 R0 与现有安装配置确定并写入 YAML。
- 在独立已知地面测试上，拟定地面高度误差 P95≤0.10 米；已观测部件在正逆转换后索引、XY 和 intensity 不变，数值误差按实现精度验证。
- 真实已复核窗口不再仅因绝对 z 截断丢失两侧边界；输出柱底缺失和高度不确定度。几何支撑不足仍可拒绝，不将缺测补成已测。
- 再现旧失败窗口及地面带仅 71 点的情况，记录是否有新合法依据，不通过降低最小点数强迫通过。

涉及：`pipeline.py`、`detector.py`、`geometry.py`、`focus.py`、`goal_detection.yaml`、`test_goal_evidence.py`、`test_goal_geometry.py`。

## 5. R2：BEV 搜索区域修复

### 工作

1. 将空间占据与时间重复观测分开：几何占据从专用 BEV 格统计；重复观测只作独立质量信息。取消“体素代表点数除以累计帧数”作为同一物理密度的解释。
2. 首选检验高度分层后的空间占据/边界结构提议，不要求网面中间必须空，也不要求两根柱先成为独立致密 blob。提议阶段允许宽松覆盖，最终真实性由 R3 的独立部件证据判断。
3. 比较现状、修正的空间占据、局部几何绕过 BEV 三种路径；原始计数旧方案只作已失败对照，不重新默认为主线。保留 YAML 中的区域数量、点数、耗时预算与截断诊断。
4. 按 R0 的单帧/0.5/1/2/5 秒矩阵比较，并保留 20/200 帧旧例；体素比较包含不降采样基线。200 帧是诊断上限，不默认提高运行延迟。相同空间重复加入同一观测不能增加独立证据。

### 测试与门禁

- 专门复现 20 帧“14→8 点、门限 11”和 200 帧“258→15 点、门限 110”的案例，证明修复的是统计口径。
- 定义提议命中：提议区域同时覆盖已标注的两侧边界及上沿的 XY 支撑范围；单柱部分可见样本另计，不要求其伪造双柱。
- 拟定 reviewed 可观测窗口提议召回≥95%；同时报告每窗口无匹配提议数、截断比例与耗时，不能靠全场一个大框获得高召回。提议区域尺寸/数量约束在开发集上冻结。
- 真实固定结构的提议不再仅因窗口长度增加而消失；由遮挡/运动导致的下降单列，不能混成统计修复收益。

涉及：`bev.py`、`accumulation.py`、`pipeline.py`、`observability.py`、`goal_detection.yaml`、`test_goal_bev.py`、诊断与评分工具。

## 6. R3：含球网的几何检测与 M1

### 工作

1. 在 R0 reviewed 局部窗口中先关闭跟踪反馈，复用正式检测器研究几何。提议区域是输入范围，标注部件坐标不得传入检测器。
2. 首选在局部竖直结构中估计水平朝向，再在局部立面坐标里分开提取左/右边界与上沿。竖线支持率、分段连续性和位置集中度分别计算，网面内点不再强迫属于某个柱种子。
3. 以双边界的平行性、间距、相对高度、底部关系及上沿连接支持形成候选；宽高先验来自独立实测/复核区间，未知时显示不确定度，不能拿候选自身尺寸反向标真值。
4. 将局部鲁棒直线拟合作首选实现；只有该方法在冻结开发反例中失败且能说明原因，才引入另一种提取方法。控制算法分支数量，不同时堆叠多套检测器。
5. 分开输出左边界、右边界、上沿、网面和地面的支撑点及残差。缺一侧或上沿时输出部分结构假设及缺失原因，不能沿默认尺寸补成高置信度完整球门。
6. 继续保留已有无横梁场景，但将“存在几何测量”和“足以确认球门”分开评分；旧 `missing_crossbar` 的测量召回并不代表已锁定。

### 测试与门禁

- 增加包含网面、斜撑、相邻围栏、树干、门形围栏缺口、非标准尺寸和一侧遮挡的 SYNTHETIC 反例。参数与真实密度/缺失统计一致，仍标明非物理传感器仿真。
- 在 M1 小集中，完整可观测正窗口逐个正确定位，已复核背景窗口不产生高置信度完整球门；样本名单预先固定，失败不得靠更换窗口消除。
- 拟定完整框中心误差 P95≤0.5 米、宽高误差 P95≤0.3 米，并检查两侧/上沿是否各有实际支撑。标注精度不足时先报告不确定度，不能据此宣布厘米级效果。
- 将 1.774 米网面组件被当“过宽柱”拒绝的旧例转成回归；允许网面组件较宽，但真正边界的宽度、残差与背景拒绝仍受约束。
- 展示原始点、实际参与点、部件支持和测量框四层同源叠加。M1 通过只写“局部窗口几何通过”，不写“全场自动识别通过”。

涉及：`geometry.py`、`detector.py`、`pipeline.py`、`synthetic.py`、`observability.py`、`DemoApp.tsx`、相关几何/候选/合成与浏览器测试。

## 7. R4：全场搜索、运动窗口与跟踪

### 工作

1. 撤去人工固定 demo ROI，保留明确的物理距离/FOV 边界。日志必须显示实际搜索范围；全局搜索不能再被 sensor 坐标中旧矩形静默限制。
2. 使用真实左右扫描/移动数据对照。先量化窗口内的结构展宽与一致性，限制混合不同姿态的观测；必要时缩短窗口或拒绝该窗口。
3. 本阶段不恢复无 IMU 点云里程计主线，不承诺靠运动补偿自动解决。若短窗口不足以观测目标，应报告可用观测时长/姿态范围，必要时补录固定雷达数据。
4. 几何测量通过后再接回现有 tracker。保持 `MEASURED_CURRENT`、`PREDICTED_RECENT`、`EXPIRED_HISTORY` 和不同 observation_signature 的确认规则，不以同一历史窗口连续出框凑确认帧。
5. FOV 收缩、失锁、重获均以真实测量与不确定度驱动；转动时不把旧 sensor 框固定在原位置继续显示成检测。
6. 将“缩短/拒绝运动污染窗口”和“有姿态依据的运动补偿”分开对照。补偿只有在实测角度或其他独立可信位姿、时间同步及标定明确时才进入实验；记录变换方向、参考时刻和残差。当前帧级位姿不能冒充逐点去畸变；无此依据时补偿项为 NOT_EVALUATED，继续评价未补偿方法的适用范围。
7. 重叠窗的 signature 变化不等于新增独立结构证据。报告相邻确认使用的来源交集、每个部件新增支撑和来源年龄，并用“同一历史结构加少量新杂波”反例检查不能靠滑窗移动累加锁定次数。

### 门禁

- 同一 reviewed 目标在人工 ROI 内/外均能被全局提议覆盖；负样本单列误提议、几何误检和错误锁定三层计数。
- 完全不可见期间错误当前测量/确认=0；ID switch=0 为拟定目标，失锁和重获时间按 device_time 报告。首次稳定确认时间不得早于所需独立观测实际出现。
- 暂停、seek、配置变化、同帧多次轮询不能制造新测量或延长轨迹。UI 显示窗口时间跨度及预测/测量区别。
- 如果只能固定雷达通过，则 M1 可保留通过，R4/M2 仍 FAIL 或因缺数据 BLOCKED，不能用静态成绩替代运动验收。

### 时间、稳定性与资源的口径

| 项目 | 记录方式与验收边界 |
|---|---|
| 观测所需时间 | 报告窗口跨度、每部件最新来源年龄，以及从进入可观测条件到首个正确完整测量/稳定确认的设备时间；未确认段不从统计中删除 |
| 算法耗时 | 同机单任务记录每阶段与整帧 p50/p95/p99/max、超预算比例和积压；不能只对成功帧计时 |
| 界面延迟 | 用可对齐的单调时钟/请求追踪测量回放投递至对应版本渲染完成；设备时间与 PC 时钟未同步时不能直接相减 |
| 跟踪稳定性 | 已复核连续片段报告正确测量时间覆盖率、最长缺测、误锁、ID switch、失锁/重获时间；按设备时间统计，不按 HTTP 轮询次数统计 |
| 框的抖动 | 仅在确认静止的条件下评价中心/宽高/yaw 的变化，并同时报告定位偏差；运动中传感器坐标变化不能全算抖动 |
| 内存与长跑 | 分开记录进程峰值常驻内存、缓存/诊断上限及磁盘增长；冷启动、预热、稳态单列，无法取得的指标填 null |

Windows 暂沿用完整计划的处理 P95≤100 ms、回放投递至显示 P95≤200 ms 目标，必须同时报告观测积累时间；5 秒积累即使计算只用 50 ms，也不等于 50 ms 首次检出。R4 记录功能与时序证据，P7 完成端到端和长跑门禁，Jetson 再独立测量。运动速度/转速范围与最大可容忍缺测时长须有动作依据，在 R0 数据清单和首次 R4 验证前冻结；未知时报告测试条件，不宣称满足应用。

涉及：`pipeline.py`、`accumulation.py`、`tracker.py`、`focus.py`、`demo_api.py`、`DemoApp.tsx`、时间证据与端到端测试。

## 8. R5：冻结与发布门禁

本节数值是拟定开发目标，不是当前成绩。R0 明确统计单位，开发集上校准后在首次最终验证前冻结 `eval_config_version`。不根据验证失败临时调宽门限；确需变更目标时先写原因、版本和新验证数据安排。

本计划的 95% 几何目标适用于已复核完整可观测窗口，取代旧完整计划中未冻结的真实 P/R 和框误差提案。部分可见、不可见及不确定样本另列，但在已复核背景/不可见区间产生的完整测量和错误确认仍必须计为误检/错误确认。不可通过排除不可见样本掩盖误报；UNKNOWN 保持不评价。匹配范围、正负样本数、TP/FP/FN、漏检率与匹配后误差一起保存。

| 层级 | 拟定退出标准 |
|---|---|
| 来源与画面 | 原始引用、掩码、框、帧/窗口/config 身份全部可复算；诊断开关不改变决策 |
| 地面 | 已知地面测试 P95≤0.10 米；退化/无支撑不能输出可信模型 |
| 提议 | reviewed 可观测窗口召回≥95%，同时受冻结的区域大小/数量预算约束 |
| 真实几何 | reviewed 完整可观测窗口 precision/recall≥95%；中心 P95≤0.5 米，宽高 P95≤0.3 米 |
| 真实跟踪 | 不可见期间错误确认=0，ID switch=0；失锁/重获/缺测持续时间逐段报告 |
| 证据规模 | 最终至少 30 个正、30 个背景窗口，来自至少两次独立录制；窗口按片段分组，至少一次录制为未用于调参的留出数据。该规模仅为初步验收，不代表充分泛化证明 |
| 困难场景 | 单柱/缺上沿/运动展宽/目标出 FOV 单列，不用常规场景均值掩盖失败 |

开发 seeds 用 0–19；已有 1000 等看过的 seeds 作回归，不再称未见验证。拟定新验证 seeds 2000–2049，首次使用前写入 manifest 并检查是否已有使用记录；若已使用则另划新集合。验证结果只用于评估，后续迭代须说明验证集复用情况。

单个修复先跑直接回归及真实短对照；阶段变更集完成后跑后端全量。涉及前端时构建并运行对应 Playwright；P3 最终退出运行真实主 PCAP 全量、跨录制对照、冻结 SYNTHETIC 矩阵、前端构建和必要浏览器用例。延迟/内存单独在无并发干扰条件下测量，Windows 结果不代替 Jetson 性能。

每次独立目录保存：命令、环境、输入 SHA、源码哈希、配置、split manifest、标注版本、逐窗口/逐帧输出、拒绝原因、混淆统计、分层指标、截图及失败清单。新增字段先更新调试契约；更新 `Plan/README.md`、本计划状态、`web/VALIDATION.md`，P3 通过后才更新 P4 的可执行状态。R5 是算法门禁，P4–P7 继续承担持久化、完整 UI、最终应用回归和资源交付；进入 P6 时检查数据是否已用于调参，不能再次把 R5 看过的录制称为未见留出集。

## 10. 实验结果决定下一步

| 观察结果 | 下一步动作 | 允许写出的结论 |
|---|---|---|
| 原始部件持续有支撑，过滤后消失 | 修 R1/R2，按部件定位丢点环节 | 预处理阻断已定位，检测尚待验证 |
| 原始与过滤后部件有支撑，几何不出框 | 在正式检测器修 R3 边界/上沿提取 | 结构模型问题，不通过调 tracker 代替修复 |
| 只有长静止窗口能恢复完整结构 | 记录最短可用时长，先验收 M1，评估应用允许的等待与运动 | 静态窗口几何可用，动态能力未证明 |
| 真值、尺寸或窗口动作未确认 | 保持待复核；继续独立工具、契约与 SYNTHETIC 工作 | 真实准确率 NOT_EVALUATED，不生成伪真值 |
| 核对方向、距离、设置并重复采集后仍缺可信部件回波 | 提出明确的补采条件或传感器能力验证 | 仅说明这些条件下证据不足，不能外推整个采集或其他目标必不可测 |
| 静止检测达标，运动后展宽/失锁 | 进入 R4 比较短窗、拒绝策略及有独立姿态依据的补偿 | 限定可用运动范围，补偿与未补偿分别验收 |

最终部署顺序为 Windows PCAP 算法与 WebUI → P4–P7 工程交付 → WSL2/Humble 集成 → Jetson Orin Nano/Humble 实测。Jetson 记录实际输入速率、端到端延迟、峰值内存、积压/丢帧、断流恢复与长跑；Windows 或 WSL2 通过均不能替代该门禁。细线能力实验可按独立计划开展，无需等待这条部署链全部完成。

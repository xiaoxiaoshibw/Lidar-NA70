# 05 开发执行规范

## 1. 开始工作前

1. 读取 `Plan/README.md` 和当前阶段文件。
2. 检查工作区实时文件树，不依赖旧交接记录猜路径。
3. 检查现有改动，不覆盖无关用户文件。
4. 明确本次对应的任务和门禁。

## 2. 代码规则

- 算法核心与 ROS2 封装分离，核心逻辑可离线单测。
- 所有阈值进入 YAML，不散落硬编码。
- PointCloud2 字段按名称和 datatype 查找，不假定固定 offset。
- 保留 header stamp、frame_id、intensity 和原始点索引关系。
- 空输入、NaN/Inf、乱序、时间跳变和参数非法必须有明确处理。
- Track ID、状态和类别 `UNKNOWN` 的语义必须稳定。
- 模型、数据集、配置和输出均带版本号或哈希。

## 3. 测试层级

### 本地测试

- 背景体素更新和衰减；
- DBSCAN 输入输出和 AABB；
- Kalman、门控、Hungarian 和生命周期；
- ROI 裁剪、采样、归一化和数据切分；
- 类别平滑和 UNKNOWN。

### Jetson 测试

- ROS2 构建与消息生成；
- PCAP 和真实设备回放；
- 节点频率、延迟、CPU/GPU 和内存；
- RViz 可视化；
- 分类推理后端；
- 故障注入和长测。

### WSL2/Humble预验证

- 本机WSL2固定使用Ubuntu 22.04 + ROS2 Humble，发行版数据安装在D盘。
- WSL2结果必须标记为 `WSL2_HUMBLE_X86_64`，不能替代Jetson/Humble ARM证据。
- 优先把build/install/log放在WSL的ext4目录，避免在Windows挂载盘上生成大量构建产物。

## 4. 证据要求

每次门禁验收至少保存：

```text
代码版本或文件哈希
运行设备和环境
完整命令
配置文件
输入数据标识
结构化指标
关键日志
失败项和下一步
```

测试失败必须保留失败事实，不得通过改写描述把失败变成通过。

## 5. 部署和资源

- 背景减除、聚类和跟踪优先使用 CPU，分类模型使用 GPU/TensorRT。
- Jetson Orin Nano 4GB 上必须限制背景体素数、点云缓存、Track 历史和批大小。
- 分类器必须支持独立关闭；关闭后运动链仍正常工作。
- 优化顺序为正确性、可观测性、稳定性、性能，不提前牺牲可调试性。

## 6. 文档表述

- 将“已运行”“已输出”“指标达标”“阶段通过”严格区分。
- MapMOS 记录写成“官方预训练方案在当前 NA70 测试中失败并退出主线”，不得写成未经证明的普遍理论结论。
- 虚拟数据结果显式标记 `SYNTHETIC`。
- 所有性能数字注明设备、输入规模、配置和数据来源。

## 7. 建图阶段（mapping job）专用规范

1. **唯一实现**：点云配准只能通过 `POST /api/mapping/jobs` 走 `backend.mapping` + `backend.mapping_jobs`。旧 `/api/captures/{id}/registration` 是兼容外壳，不得再出现第二套算法。`web/backend/registration.py` 已取代，仅供历史合成测试。
2. **结果必须落盘**：任务记录、配置、轨迹（JSON/CSV）、逐帧质量（JSONL）、关键帧、地图元数据、地图分块、PLY、PCD、`validation.json` 全部写入导入记录目录，服务重启后可复查。内存里只有状态，不是结果。
3. **阈值来自数据**：配准与地图阈值集中在 `web/backend/mapping.yaml`，并随任务记录 `config_version`。先用静止噪声基线与真实采集统计确定阈值，再判定通过；不得先写固定阈值再反向解释结果，也不得为了得到「通过」而放宽对应距离。
4. **帧状态与融合纪律**：`quality_failed`、`insufficient_points`、`degenerate_geometry`、`timestamp_invalid`、`tracking_lost` 的帧一律不融合。失锁后的帧继续标注并可在 WebUI 查看，不允许隐藏。重新初始化必须开启新的轨迹段，不拼接无约束坐标。
5. **禁止夸大**：没有回环检测和位姿图优化前，页面与文档只能写「点云里程计」「配准累计」「体素地图融合」，不得写「完整 SLAM」。
6. **建图证据包**：每次验收保存 `validation.json`（含 `claims` 块）、`job.json`、`trajectory.csv`、`frame_quality.jsonl`、`map.ply`、地图分块索引与 `export/mapping-evidence.zip`，并注明设备、Python/NumPy 版本、输入 SHA-256、配置版本、耗时与峰值内存的采集口径。
7. **失败保留**：真实数据上配准失败时必须同时保留失败任务目录与失败原因，并在 `Plan/MASTER_开发与验收总计划.md` 与 `web/VALIDATION.md` 记录实测数值；不得删除失败任务或改写描述。
8. **性能数据口径**：`validation.json.peak_memory_mb` 是**整个服务进程**的峰值常驻内存（Windows PeakWorkingSetSize／Linux VmHWM），不是单个任务内存；计数器不可用时写 `null`，不得写 0 冒充有效读数。

# 细线回波验证与逐级开发计划

日期：2026-09-21。状态：PAUSED；W1 原始工具已实现，真实细线归属 NOT_EVALUATED；W2–W5 均 NOT_RUN。用户已将近期主线恢复为[足球门识别](足球门识别主线开发计划.md)，本计划及证据保留，待以后恢复。

开发交付：[W1 工具与验证记录](evidence/thin-wire/20260921-w1-development/REPORT.md)、[使用说明](../docs/THIN_WIRE_W1_USAGE.md)、[现场采集卡](../docs/THIN_WIRE_W1_CAPTURE_CARD.md)、[数据契约](../docs/THIN_WIRE_W1_CONTRACT.md)。24 项 W1 与 13 项解码测试通过，既有 `1.pcap` 五种窗口完成工具验证；这些结果不构成细线回波通过证据。全量回归中的转台导出竞态失败另行保留。

本计划保留此前确定的五步顺序：固定雷达确认细线回波 → 距离阶梯 → 人工区域线提取 → 全视场 → 运动与实时。恢复本路线时仍从 W1 开始，回答“已知位置的真实细线有没有可信回波”。当前足球门主线不改变本计划的证据边界，足球门识别成功也不能自动证明细线能力。

遵循 [开发执行规范](05_开发执行规范.md)。当前环境为 Windows 本机离线 PCAP 与 WebUI；复用正式解码、回放与来源追踪。此文是执行计划，不表示已经采到细线、完成测量或证明 200 米可行。

## 1. 五步顺序与阶段交付

| 阶段 | 只回答的问题 | 必须交付的证据 | 进入下一步的依据 |
|---|---|---|---|
| W1 固定雷达看原始数据 | 已知位置的细线有没有可信回波？ | 原始点、对应时间、独立确定的目标位置、背景对照与重复录制 | 同一条件下重复观察到与目标位置一致且能与背景区分的支撑；不能仅凭 ROI 有点认定 |
| W2 距离阶梯 | 在什么距离、什么积累时间下还能观察到？ | 20/50/100/150/200 米逐级对照，单帧与 0.5/1/2/5 秒统计、失败与缺数据项 | 确定至少一个可重复的距离/时长工作范围，再在该范围做线提取；无需先达到 200 米 |
| W3 人工指定区域提取线 | 已有回波能否拟合可信线段？ | 支撑点数、来源时间、拟合误差、覆盖长度、最大断裂间隔及背景反例 | 在冻结的距离/时长条件下，独立片段的线段与支撑一致，误差和背景拒绝达到预先冻结标准 |
| W4 全视场 | 能否与树枝、围栏等区分？ | 独立录制的目标/背景真值、漏检、误检、定位误差与典型失败 | 全搜索范围内的正例与困难负例达到冻结指标；不使用目标位置引导搜索 |
| W5 运动与实时 | 雷达运动后能否稳定输出？ | 运动条件、补偿依据、连续正确输出、缺测、延迟、资源和部署实测 | 在明确运动范围与实时预算下通过；最终部署性能由 Jetson Orin Nano/Humble 实测 |

每阶段状态分别记录 NOT_RUN、IN_PROGRESS、PASS、FAIL 或因缺数据 NOT_EVALUATED，不能用后续模块输出替代前一步证据。遇到缺少原始回波时先核对采集条件，不能靠拟合、跟踪或默认尺寸补成已测目标。

## 2. W1：第一轮具体执行与证据

### 采集条件

1. 雷达固定安装、固定朝向，目标也保持静止。优先从可布置的近距离开始，例如 20 米；填写实际测距及误差，不能把名义距离当实测距离。
2. 记录线径、材料/表面、可见长度、姿态/朝向、垂度、遮挡、背景距离、雷达安装姿态、设备/固件与采集设置。线径或位置未知时如实记 null，不默认等同目标导线。
3. 目标位置须来自独立测量、现场参考点及其坐标变换，保存端点/路径和位置不确定度。现场照片辅助证明场景，不能单独替代三维米制位置。观察区域在查看检测结果前确定；不得用拟合出的线反向定义目标真值。
4. 首批建议每个条件至少 3 次独立录制、每次连续至少 30 秒，作为可行性检查规模。背景优先采用同机位、同设置、目标可移除时的有线/无线成对采集；不可移除时记录相邻等尺度空区域及其局限，不能把邻域对照冒充同位置无线对照。
5. 核实目标处于实际扫描范围内。记录目标角位置附近的有效扫描方向、无效距离及缺包情况；如果不能确认照向目标，结论保持证据不足。

### 原始数据与时间

- 以正式解码的有效 XYZ/intensity 为原始点依据，保留 PCAP、原始距离/角度码及可用时间信息。使用 ROS2 驱动作为协议参考，不另造细线解码公式；无效距离不能补成有效点。
- 不经过球门的 50–130 米范围、绝对高度、0.5 米体素及球门尺寸规则。先检查整个解码/后端/渲染路径，避免 20 米或 200 米数据在显示前已被隐藏；人工观察区域是可追溯裁剪，区域外原始数据仍保留。
- 每点保存 `(capture_id, frame_index, point_index)`、对应设备时间及时间粒度；只有帧/包时间时明确标注，不能虚构逐点时间。原始 intensity 仅作未标定强度记录，不称为反射率或跨设置可比较的绝对信号强度。
- 比较单帧及 0.5、1、2、5 秒因果积累，按设备时间选择同一录制的窗口并报告实际跨度。约 10 Hz 的帧数不是精确秒数，100 包成帧也不代表完成一轮重复扫描。时间跳变不拼窗，起始不足时长单列。
- W1 原始基线不降采样；如查看现有过滤/体素影响，只输出同源附加对照。不能只交渲染抽样云或把抽样后的点数当回波数。重叠窗、重复点引用和多次 UI 轮询不能充当独立重复试验。

### 第一轮必须拿到的四项证据

| 证据 | 内容 |
|---|---|
| 原始点 | 同一窗口的正视/侧视/俯视图和可读取点数据；标出目标位置及误差范围、疑似目标支撑、周围背景；每个支撑可追溯 |
| 对应时间 | PCAP 身份、起止帧/设备时间、实际积累时长、有效帧数、来源年龄、时间/缺包质量；展示支撑随时间出现的情况 |
| 目标位置 | 独立确定的线位置、距离、线径、朝向、坐标系及转换、不确定度和静止依据；未确认项逐一列出 |
| 背景对照 | 同条件目标/背景的原始统计和图；区分目标位置附近的所有点与经位置/背景对照支持的目标一致回波，保留混淆点 |

统计至少包含目标区域总点数、目标一致的支撑点数、不同来源帧数、每个独立窗口是否存在支撑、位置残差、原始强度分布及背景对应数值。ROI 点数不等于目标回波数；未能可靠归属的点记为不确定。只有采样方向与次数可靠时才计算相应的命中比例，并明确分母；不把“有点窗口占比”直接称为传感器探测概率。

### W1 结论规则

- **已观察到可信回波**：独立目标位置与回波一致，重复录制可复现，背景对照能支持归属。报告成立的具体距离、线径、朝向和积累时间；进入 W2。
- **证据不足**：目标位置、时间、扫描覆盖或背景归属不清，先补测/复核。不能用一次偶然点或模糊截图宣告成功。
- **这些条件下未观察到可信回波**：核对方向、距离、设置并重复录制后仍缺支撑，记录实际试验次数与原始证据，调整条件或评估硬件。不能外推成所有距离、线径与朝向都不可测。

W1 不要求自动拟合线或完整识别；成功依据是可追溯、可归属、可重复的真实回波。

## 3. W2：逐级建立距离与积累时间范围

从 W1 的可观察条件出发，按 20、50、100、150、200 米名义阶梯推进，逐档记录实际距离；当前档证据不足时先重复核对或补中间距离。各距离保持同一目标及设置，必要变化单列条件，不能把材料/线径改变后的收益归因于算法或距离。

每档运行单帧与 0.5/1/2/5 秒对照，保留原始基线和背景。结果表至少列出：实际距离、目标属性、录制编号、窗口时长、目标一致支撑/独立来源数、有支撑窗口数及总窗口数、残差/强度、背景数和结论。多个时长变体归同一录制组，不随机拆入开发与验证。

输出“在本批条件下可重复观察的距离—积累时间范围”。只有长时间积累可观察时明确写静态积累能力；200 米为验证目标，不能提前写成有效量程。后续线提取在已获得可信回波的范围开始。

## 4. W3：人工区域内提取可信线段

人工 ROI 只限定搜索空间，拟合不得读取真值端点作为输出。先采用有界的鲁棒三维直线拟合，输出有限线段及原始内点；支撑不足、只有孤立团块或明显不符合直线时拒绝。存在明显垂度时报告直线假设的适用范围，需要分段/曲线模型时另列依据。

必须报告：唯一原始支撑点数和独立来源、正交残差 RMS/P95、沿拟合方向的投影跨度、实际有支撑的覆盖长度/比例、最大内部断裂及已知目标两端缺失。覆盖按预先固定的投影区间宽度计算，不把首尾跨度称为整段覆盖；不能靠大量重复观测把少数位置包装成连续线。

阈值从开发数据的噪声、目标长度与标注误差确定，放入独立 YAML 并在验证前冻结；目前不虚构通用最小点数或误差门限。原始/过滤/降采样版本作同窗对照，并在独立背景及树枝/围栏反例上验证不能随意拟出可信线。

## 5. W4：全视场与独立录制验收

取消人工目标 ROI，显式记录实际距离和 FOV 范围，在独立录制上自动搜索。开发/验证按完整录制或有隔离的连续片段分组，不让重叠窗口或状态缓存跨分组。背景至少覆盖树枝、围栏、杆件、建筑边缘及纯背景。

区分“检测到线形结构”和“识别为目标导线”。仅凭局部直线几何可能无法区分电线、围栏横杆或树枝；有歧义时输出未知线结构，不强行标为导线。

在 reviewed 目标窗口报告 TP/FN、召回及几何误差，在正负窗口统计 FP、precision 和每分钟误报；无目标录制单列，UNKNOWN 不伪造真值。报告样本数、可见性、距离/时长分层及失败清单，未检出不能从误差报告中消失。最终标准在首次独立验证前冻结。

## 6. W5：运动、实时与部署

先保持同一目标和已验证距离，逐级增加雷达转动/平移并记录独立动作依据。比较短窗、拒绝受污染窗口以及有可信位姿/时间同步依据的补偿；不将帧级姿态当作逐点去畸变，也不恢复已退出主线的无 IMU 里程计作为默认方案。

记录正确输出覆盖时间、最长缺测、误报、定位误差、首次发现和重获时间。静止时统计抖动；雷达运动中的传感器坐标变化不能全部算成目标抖动。预测与当前回波支撑分开输出。

分别测量观测积累等待、解码/算法耗时、排队、传输/显示延迟和输出速率，报告 p50/p95/p99/max、积压/丢帧及冷启动。仅提高输出刷新率不等于每次都有新测量；5 秒积累后快速出结果不等于低延迟实时识别。

最后按 Windows 回放 → WSL2/Humble 集成 → Jetson Orin Nano/Humble 实际设备输入验收推进。实时预算、运动范围、容许缺测和长跑时长在验证前明确；记录进程峰值常驻内存、缓存上限、断流恢复，Windows/WSL2 成绩不替代最终 ARM 性能证据。

## 7. 当前缺口与执行交接

本轮已检查现有 PCAP 文件清单，但尚未指定细线 PCAP、独立目标位置和匹配背景录制；已有球门 PCAP 不自动成为细线真值。下一步核对目标采集说明后执行 W1 的真实归属复核，真实回波结论维持 NOT_EVALUATED。

首轮工具 `tools/audit_thin_wire.py` 已复用正式解码器，支持设备时间窗、未经体素化的点导出、目标/背景区域和原始引用；配置为 `tools/thin_wire_config.yaml`。已有球门 runner 的 `--window` 是帧数、`--voxel 0` 表示采用默认值，不能当作细线原始模式。参数与来源契约已单独记录，实验配置独立于 `goal_detection.yaml`。

每次实验在 `Plan/evidence/thin-wire/<run>/` 新建目录，交付如下。当前已有工具诊断产物，已知位置细线的正式实验产物仍待生成：

- `manifest.json`：输入 SHA、源码/config 哈希、命令、设备环境、采集条件、目标位置/误差、录制与分组清单。
- `raw_windows/`：目标/背景窗口的原始有效点、索引/时间和缺失质量信息；PCAP 留在采集目录并通过哈希关联，不提交 Git。
- `window_metrics.jsonl`：每个真实窗口的距离/时长、点数、归属、时间来源、背景对照与结论。
- `figures/`：同源三视图、位置范围及时间对照；标注渲染抽样和不确定点。
- `REPORT.md`：证据是否支持目标归属、已试/未试条件、失败原因、下一步；测试与性能结果分别注明环境。

工具实现需验证空窗、无效点、时间跳变、窗口边界、重复来源、目标 ROI 外/距离范围外点、20/200 米数据未被球门过滤及导出/显示来源一致性。SYNTHETIC 只验证工具和算法行为，不能替代 W1 真实回波证据。

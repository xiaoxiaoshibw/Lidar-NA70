# NA70 固定点转台操场建图实施与验收计划

版本：v1.0  
日期：2026-09-15  
路线状态：`SELECTED`  
任务定义：固定雷达旋转中心，通过转台记录真实航向角，将多个静止视角变换到统一坐标系并融合为操场观测地图。

## 1. 决策与边界

本路线替代当前“无 IMU 移动雷达纯点云里程计”主线。第一阶段不开发移动里程计、回环、位姿图或完整 SLAM，也不依赖 ICP 从操场远场点云中反推大角度航向。

本路线的正式名称为“固定点转台多视角建图”，不是 SLAM。它要求：

- 转台底座和旋转中心在整次采集中保持不动；
- 雷达安装高度、横滚角和俯仰角保持不变；
- 每个视角的航向角由转台刻度、编码器或角度传感器给出；
- 转动期间的点不进入地图，只融合停稳后的有效时间段；
- 点云配准只允许做小范围残差校验或微调，不能取代实测角度；
- 地图表达的是该固定观测点能够看到的操场表面，不宣称恢复被遮挡区域或建筑内部。

如果后续需要雷达沿操场移动，应另立带 IMU、轮速或 RTK 的移动建图任务，不在本计划中混入。

## 2. 为什么采用离散驻留扫描

NA70 为双楔镜非重复扫描。连续转动时，一个积累窗口内既包含扫描覆盖变化，也包含雷达姿态变化；当前数据又没有可信逐点时间，无法做精确的窗口内运动去畸变。

第一版因此采用以下流程：

```text
转到目标角度
  → 锁紧并等待机械振动停止
  → 记录稳定角度
  → 静止扫描 10 秒
  → 标记有效时间段
  → 转到下一个角度
```

既有实验表明，10 秒静止积累比短帧具有明显更稳定的覆盖和配准表现，因此第一轮以每个角度 10 秒有效扫描为默认值。后续只有在真实覆盖统计通过后，才能缩短驻留时间。

## 3. 硬件与标定要求

### 3.1 最小硬件

- 刚性三脚架或固定底座；
- 可锁紧的水平转台；
- 角度读数装置，优先使用绝对值编码器，其次使用带游标的高精度刻度盘；
- 水平仪；
- 现场角度与时间记录终端。

普通粗刻度转盘只能用于流程试验。远场横向误差近似为：

```text
横向误差 ≈ 目标距离 × 航向角误差（弧度）
```

例如 80 m 处若希望角度引入的横向误差不超过 0.20 m，航向误差必须小于约 0.143°。因此正式验收建议使用分辨率不低于 0.1°、重复性优于 0.1°的角度记录装置；最终门限根据现场目标距离和地图允许误差冻结。

### 3.2 坐标与外参

定义以下坐标系：

- `map`：固定世界坐标系，零度视角为 x 轴正方向；
- `turntable`：转台旋转轴坐标系；
- `lidar`：NA70 原始点云坐标系。

必须标定并保存：

- 零度方向；
- 正角度方向；
- 雷达相对转台的固定横滚、俯仰和航向；
- 雷达原点到转台旋转轴的水平偏移和高度差；
- 转台回零重复性和锁紧后的角度漂移。

正式变换使用：

```text
T_map_lidar(theta) = T_map_turntable × Rz(theta) × T_turntable_lidar
```

不得默认雷达光心恰好位于旋转轴上。只有实测偏移可以忽略时，才能把平移外参置零。

## 4. 现场采集方案

### 4.1 采集前检查

1. 固定底座，标记三脚架三个落脚点和转台中心投影点。
2. 调平雷达并记录安装高度。
3. 选择操场中线或其他可复现方向作为 `0°`。
4. 在相邻视角共同可见区域保留球门、围栏、建筑边缘、立柱等固定结构。
5. 避开大量人员、车辆和剧烈摆动的树冠。
6. 启动 PCAP 后先在 `0°` 静止采集 20 秒，用于时间和静止基线。

### 4.2 推荐角度序列

第一轮从以下序列开始：

```text
0° → -10° → -20° → -30° → -40° → -50° → -60°
   → -50° → -40° → -30° → -20° → -10° → 0°
   → +10° → +20° → +30° → +40° → +50° → +60°
   → +50° → +40° → +30° → +20° → +10° → 0°
```

每个角度执行：

- 转动完成后等待至少 2 秒；
- 锁紧并确认角度读数稳定；
- 静止扫描 10 秒；
- 记录有效扫描开始和结束时间；
- 发现碰撞、滑动或人员遮挡时，将该段标记为无效并重采。

往返角度序列用于检查机械回差、重复视角重合和地图重复性。若相邻视角共同固定结构不足，应把步长从 10°减小到 5°；不得通过放宽点云对应距离掩盖覆盖不足。

### 4.3 文件组织

优先录制一份连续 PCAP，并配套一个角度日志 CSV。连续文件能够保留统一时间轴，转动段通过日志明确排除。

角度日志最少包含：

```csv
segment_id,yaw_deg,settle_start_s,valid_start_s,valid_end_s,direction,valid,note
001,0.0,0.0,2.0,22.0,start,true,initial baseline
002,-10.0,25.0,27.0,37.0,left,true,
```

同时填写：

```text
PCAP 文件名：
采集日期和位置：
转台型号/编码器型号：
角度分辨率与重复性：
零度参考物：
雷达安装高度：
雷达到旋转轴偏移：
开始与结束时间：
底座是否移动：
现场动态干扰：
操作人员：
```

原始 PCAP、角度 CSV、转台标定 JSON 和现场照片构成一套不可拆分的输入。

## 5. 数据处理与算法流程

```text
PCAP + angle_log.csv + turntable_calibration.json
  → 正式 NA70 解码
  → 按日志切分稳定驻留段并排除转动段
  → 每段使用同一 SweepBuilder 形成覆盖充分的静止子图
  → 距离、强度、有限值和动态点质量检查
  → 应用 T_map_lidar(theta)
  → 相邻角度固定结构一致性验证
  → 可选的小范围残差微调
  → 体素融合与来源保留
  → PLY/PCD、预览图和完整证据包
```

### 5.1 位姿来源优先级

1. 转台实测角度与标定外参；
2. 回零和往返重复视角的几何验证；
3. 小范围点云残差微调；
4. 纯点云全局搜索仅保留为诊断，不进入正式地图位姿。

残差微调必须受角度先验约束，默认只允许修正编码器误差量级的 yaw 和旋转轴偏移误差量级的平移。修正范围写入 YAML，并在报告中同时保存修正前、修正后指标和最终变换。

### 5.2 融合纪律

- 转动段、未停稳段、时间异常段和角度缺失段不融合；
- 每个角度先生成独立子图，验证通过后再进入全局地图；
- 地面不能淹没球门、围栏和建筑立面等验收结构；
- 树冠、人员和车辆不作为刚性对齐依据；
- 体素必须保留来源角度、时间段和点数，便于定位重影来源；
- 质量失败的子图必须保留报告，但不进入正式融合结果。

## 6. 工程落点

现有 `backend.decoder`、`backend.sweeps`、`backend.mapping.VoxelMap` 和持久化 mapping job 继续作为唯一生产链基础，不复制第二套解码或地图实现。

建议按以下位置实施：

- `web/backend/turntable.py`：角度日志校验、外参模型、固定点位姿生成和驻留段质量状态；
- `web/backend/turntable.yaml`：驻留时间、角度容差、距离范围、体素和残差微调门限；
- `web/backend/mapping_jobs.py`：增加 `turntable` 建图模式并落盘全部输入与变换；
- `web/tests/test_turntable.py`：角度方向、旋转轴偏移、时间分段、回差、非法日志和融合测试；
- `tools/validate_turntable_capture.py`：调用生产模块生成采集预检报告，不另写算法；
- `tools/build_turntable_map.py`：调用生产 mapping job 的离线入口；
- `web/frontend/`：提供角度 CSV、标定 JSON 导入，显示每个角度的有效性、变换和来源着色地图。

现有 `tools/validate_playground_stitch.py` 和 `backend.cross_capture` 可作为诊断参考，但其中从点云搜索大角度 yaw 的逻辑不得直接升级为正式位姿来源。

## 7. 分阶段任务与门禁

### T0：冻结采集和坐标合同

任务：

- 确定角度装置、零度、正方向和安装外参记录方式；
- 冻结 `angle_log.csv` 与 `turntable_calibration.json` schema；
- 使用合成点验证旋转方向和偏心变换公式。

门禁 `TG0`：同一点在多个已知角度下变换后能够回到同一世界坐标；非法角度、重叠时间段和缺失标定被明确拒绝。

### T1：完成首轮转台采集预检

任务：

- 按第 4 节完成一份往返角度 PCAP；
- 输出每个驻留段的包数、点数、覆盖、时间异常和稳定性；
- 核对回到 `0°` 后的重复视角。

门禁 `TG1`：所有正式角度都有有效驻留段；无底座位移；回零角度和重复点云未出现超门限变化；相邻角度持续包含共同固定结构。

### T2：完成外部角度刚体拼接

任务：

- 按实测角度与外参变换各角度子图；
- 输出按来源角度着色的地图；
- 计算相邻视角与重复视角的固定结构一致性。

门禁 `TG2`：回零子图不形成明显双层；球门、围栏和建筑边缘在相邻视角交叠区保持单层；所有融合子图均有可追溯角度和质量记录。

### T3：受约束残差微调

任务：

- 只在固定结构上比较“不微调”和“受约束微调”；
- 使用留出结构验证微调没有把错误对应变成更好看的训练指标；
- 冻结微调门限。

门禁 `TG3`：留出结构误差改善，往返角度修正一致，且修正量不超过硬件误差预算；否则关闭微调，保留纯外部角度结果。

### T4：完整操场观测地图与独立复采

任务：

- 生成全角度 PLY、PCD、地图元数据和可视化；
- 使用不参与调参的第二次同路线采集复验；
- 对球门宽度、围栏线、建筑边缘和已测现场距离进行检查。

门禁 `TG4`：独立复采在冻结配置下通过；固定结构重影和几何误差满足预先冻结的现场容差；地图明确标注未观测和遮挡区域。

### T5：WebUI 与 Jetson 验收

任务：

- 在 WebUI 中选择转台模式、导入角度日志、查看子图状态并导出地图；
- 本机完成算法正确性和回归；
- Jetson Orin Nano/Humble 完成实时回放、资源、时延和长测。

门禁 `TG5`：后端、前端和浏览器测试通过；Jetson 上无队列持续积压，资源与处理时间报告完整。

## 8. 指标与证据包

第一轮采集先冻结噪声基线，再确定数值门限。至少报告：

- 角度装置分辨率、重复性和回零误差；
- 每个驻留段的有效时长、包数、点数和覆盖率；
- 相邻角度共同固定结构比例；
- 修正前后的最近邻距离中位数和 95 分位数；

## 10. 停止条件

出现以下任一情况时停止融合并重新采集或重新标定：

- 底座或旋转中心发生移动；
- 角度日志无法与 PCAP 时间对应；
- 转动段与静止段无法可靠区分；
- 回零点云出现持续的整体平移或旋转；
- 相邻角度没有共同固定结构；
- 编码器误差预算已经大于地图允许误差；
- 只有通过大范围 ICP 搜索或放宽门限才能消除重影。

一句话执行原则：**用转台测得位姿，用点云验证位姿；只融合停稳后的扫描，不让配准算法猜测已经能够直接测量的角度。**

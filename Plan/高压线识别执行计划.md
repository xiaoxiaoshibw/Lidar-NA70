## 0. 用户需求与前提

用户要求：

> 在**静止的 PCAP 包**中识别 **200 m 外的高压线**，制定计划 → 开发 → 审查交付。

与现有路线的关系：

- **物理门禁本任务不重走**：[细线 W1 计划](细线回波验证与逐级开发计划.md) 与 [机载 S1 计划](无人机单根高压线识别场景与可行性计划.md) 已要求先用**独立测量、同机位背景、可控细线**建立真实回波归属。该程序是用户或其合作方到**户外实地**执行的任务；本任务只能就**现有静止 PCAP 库**与合成夹具取得进展，不代替实地采集。
- **200 m 是用户需求**，在既有路线设置中是**探索档**（[W2 距离阶梯](细线回波验证与逐级开发计划.md)、[S2](无人机单根高压线识别场景与可行性计划.md)），不是已承诺能力。所有口径写为「在已验证工作包络内」「200 m 待实测检验」。
- **静止**满足 W1/W3 的固定雷达前提；PCAP 离线策略与 [S2/W3](无人机单根高压线识别场景与可行性计划.md) 一致。

决策原则：不虚构独立导线真值，不把合成或既有 PCAP 当作真实导线发现证据；对几何上无法确认为高压线的线形检出标记 `UNKNOWN_LINE`；不降低门禁、不做告警/避障能力声明。

## 2. 验收口径（不可降级）

遵守 [NA70_WIRE_DEBUG_ACCEPTANCE.md](../docs/NA70_WIRE_DEBUG_ACCEPTANCE.md)。高压线真实检出必须满足下列全部条件，否则保持 `NOT_EVALUATED` / `UNKNOWN_LINE`：

1. **独立真值**：三维端点/可见区间/线径/材料由现场测量或可靠资料给出，review_status=`reviewed`。照片单独不可；合成只标 `SYNTHETIC`，不进 TP 分母。
2. **同机位背景对照**：高压线安装与移除两批 PCAP 至少各 3 次、≥30 s；或公共基准下载 / 用户认可的真实含线场景真实数据（仍要测量位置和背景对照）。
3. **类别判定**：几何线形且不能区分高压线/普线/拉线/树枝时 `UNKNOWN_LINE`；只有独立上下文证据（如记录安装位置对应）才可标 `LINE_WIRE`。不凭线形写电压等级。
4. **评分**：按完整 capture 分组 frozen YAML 阈值一次性验证；列 TP/FN/FP、每分钟误报、覆盖/缺口、困难负例清单。子集分母不足时 `NOT_EVALUATED`，不得填 0。
5. **证据**：每条候选有原始 ID 支撑、有 stage trace、有 PCAP SHA、配置哈希；结果包落盘不可覆盖。

200 m 的任务输出**只允许是**：在含高压线数据的 frozen 验证集上，在 200 m 真值线段位置提取到稳定有限线段 + 上述证据；否则“未证明”，不升级为“成功识别”。

## 3. 执行阶段（按当前静止 PCAP 库与后续采集规划）

P0 已先行交付；P1–P4 为本任务主工程；P5 为真实数据验收衔接。所有阶段都遵守[架构](docs/NA70_WIRE_ARCHITECTURE.md)/[算法](docs/NA70_WIRE_ALGORITHMS.md)；阶段完成即更新本文档与 `Plan/README.md`。

### P0 候选方位目录与 200 m 扫描-机会扩展（本任务启动即实施）

- 输入：静止 4 PCAP、S0 工具、`wire_scene.py` 射线层。输出：`tools/scenarios/hv_candidate_catalog_v1.json` + `Plan/evidence/hv-line/20261003-p0/`。
- 行动：
  1. 用 `run_wire_scene_s0.py` 在 20/50/100 m 已完成基础上补 150/200 m 方向-交会审计，列每 0.5/1/2/5 s 交会数、覆盖长度与最大缺口（即使计数低也如实记录）。
  2. 对静止库生成 `hv_candidate_catalog_v1.json`：每个 PCAP 的静止段、>150/>200/>300 m（97/130 s 与 66 s 两档）原始回波统计、>200 m 点随时间的逐窗直方、方位/俯仰集中度（方向直方）、可疑典例清单（cluster 大小/方向/距离带头），全部标 `RAW_OBSERVATION`、`review_status=unreviewed`、`geometry_role=candidate_not_truth`。
- 退出条件：目录可重复生成；报告明确指出 catalog 不是真值；200 m 扫描机会实测（原 S0 扩展）与目录统计一并落盘。

### P1 观测核心补齐（架构 R1）

- 目标：删除「现有 W1 工具是单窗解码」约束，给后续 ROI 线段提取提供共用因果时间窗。
- 行动：`packages/na70_core/windows.py` 增量 ring buffer 包级因果窗口（按捕获分段、容量受限、与 thin_wire.select_window 对账一致）；`observations.py` 不变；分块回放与一次性回放同 ID；时间质量（缺时/倒退/间隔）断段；现有 W1 API 兼容。
- 退出条件：分块 vs 整片对账一致；坏时间不跨段；容量超限显式拒绝；旧 W1 测试通过且 2-3 项新契约用例通过。

### P2 W3 高压线 ROI 线段提取（架构 R4）

- 目标：给人工或 catalog 提供的 ROI 提取有限三维线段，可判别可信度，但不凭此判为高压线。
- 行动：`packages/na70_core/wire/`（`proposals.py`、`fitting.py`、`validation.py`、`tracking.py` 占位、`pipeline.py`），加装 pyRANSAC-3D ≥0.7 固定版本；适配器固定 seed、过滤退化样本、最终内点重算。W1 时间窗扩展距离档，新增目标/背景 ROI 比较。`web/backend/wire_api.py` 增 `/api/wire/w3`（运行、配置白名单、持久化 stage trace、运行包）。工作台可加 ROI 标注页（接 AnnotateApp 抽出的点选/标记组件）。
- 关键产出：ROP 内点 RMS/P95、沿拟合方向投影跨度、有支持区间占比、最大内部断裂、最近距离、来源 ID、窗口/候选级 stage trace。W1 的 `NOT_EVALUATED` 保留。
- 退出条件：合成单线/平行线/无目标/树枝反例通过；调用 ROI 提取时真值端点绝不进入拟合；YAML 阈值独立 wire_detection.yaml；审计 catalog 中的可疑典例能得到明确的 line-fit 接受/拒绝和原因。

### P3 静止场点实测 + 200 m 真值建立（代替现场可控实验的可行路径）

- 背景：P0 表明现有库**没有独立测量过的 200 m 高压线真值**，光几何 catalog 不足以验收。用户需要 200 m 高压线，可控替代线要在室内/操场等距布置 200 m 难度极高且并不对应真实架空材料。可行路线为 **受控实地测量**：
  1. 用户提供或本任务代理一项实测外勤（在已知位置一段 200 m 左右可见的线下安全距离可回收的替代品视为 sub-option；优先选择能在测量安全范围内独立确定三维端点的目标）。记录三维端点/线径/材料、安装朝向、背景和 PCAP SHA。
  2. 如果确切高压线不可控，取**同期同机位有/无目标**两批静止 PCAP（固定机位抬高雷达对准 200 m 处架空线）+ 现场测量/照片/地图对照，独立管理员/用户 review 三维位置。
  3. 数据进 `radar_capture_data/hv-line/`，真值按 `wire-truth-v1` 录入，背景可以来自目标移走、视线遮挡或同机位其它方向。
- 交付：3+3 次录制（每次 ≥30 s）、目标端点不确定度、清单；证据在 `Plan/evidence/hv-line/...`。
- 退出条件：有 reviewed 真值 + 同机位背景 + 静止证据。该阶段**只能等待现场窗口**，期间并行推进 P1/P2/P4/P5 有关纯软件/合成部分。
- 警戒：不通过 S0 交会数、不比照旧 PCAP 反推「高压线测到了」；不因为薄光斑理论可达就宣称 200 m 能力。

### P4 W4 全场搜索 + 高压线评判（架构 R5）

- 前提：P2 段提取通过、P3 取得 reviewed 真值。限制在未验证的候选集上也可先做 SYNTHETIC 全场，但真实门禁要等 P3。
- 行动：`wire/proposals.py` 加前向投影占据 + HoughLinesP（先加装 opencv 或纯 numpy 实现，二选一，固定版本）、保留简单几何/PCA 对照；`evidence/scoring.py` reviewed-only scorer；`wire_api.py` 增 `/api/wire/w4`；工作台 W4 页展示 TP/FN/FP、每分钟误报、困难负例索引、directed-to-failure 索引。
- 退出条件：独立录制（P3 录制或添加的运动慢变段）上，在 frozen 阈值下达到预先在 P2/W2 数据上冻结的 TP/FP 门槛；输出 `LINE|UNKNOWN_LINE|NO_CURRENT_MEASUREMENT` 三态，预测与测量分桶；200 m 只有实验结果可报才算数。

## 4. 技术选型决定（记录，后续如有冲突回这里）

| 项目 | 决定 | 理由 |
|---|---|---|
| 拟合库 | pyRANSAC-3D ≥0.7.0（Apache-2.0）固定版本 + adapter 层，优先 | 已做适配分析（全局 random 固定 seed、退化输入过滤、对外契约以原始 ID 计）、许可兼容；自写 W3 拟合重复劳动且不可替换性弱 |
| 图像提议 | OpenCV HoughLinesP 作为首对照；或纯 numpy 投影聚类替代；两者均只用于提议，真值验证仍走三维拟合 | 门径先比 Hough 与 PCA，取 evidence 好的；不直接信图像线 = 导线 |
| 曲线扩展 | SciPy `least_squares` 稳健损失，仅在长跨度系统垂度明确时启用，参数可辨识性须单报 | 设计稿已有说明 |
| 依赖验证流程 | 新增 lock 条目须含源码哈希 + Jetson(ARM64)/Windows(3.12) 兼容性检查记录 | 架构 §2.1 明确说了不能把本地锁文件直接视作 Jetson 可用 |
| 数据分桶 | MEASURED_CURRENT / PREDICTED_RECENT / NO_CURRENT_MEASUREMENT / UNOBSERVABLE 严格分开 | 不支持把静态长积累当实时能力；200 m 长积累窗决不能宣传为实时预警 |

## 5. 停止与回退

与 W1/机载计划一致：

1. 若完成 P0 与 catalog 后，`P2` 在受控实地数据上 W1 归属仍 `NOT_EVALUATED` 或 `FAIL`，**停止 200 m 识别成功宣传**，不再推进 W4/W5，保留代码与失败证据。可以**只输出「在本批静止 PCAP 上自动检测到以下 UNKNOWN_LINE 线结构，来源可得」**，不利用模型假装是高压线。
2. 任一阶段真实结果不能靠调低阈值绕过；调整阈值必须重跑独立验证，且阈值版本号升级。
3. 旧入口始终可用；失败时切回并将新旧差异写 evidence，不改写历史记录。

# IMU 数据与雷达主机时间关联前置检查

**状态：`DIAGNOSTIC_ONLY`，位置轨迹 `NOT_EVALUATED`。** 用户说明雷达和 IMU 同时开始和结束录制；两个流也均保存主机 Unix 接收时间，可在同一时间轴上做粗关联。主机接收完成时间不是设备采样时间，同时启停不能确认两路各自的传输和缓冲延迟相同。

## 实测事实

输入是 `radar_capture_data/na70_sessions/20261104-170341/imu_frames.jsonl`，SHA-256 `c661d5510be9e797e4d5fecd5dcf812bb0ab676f6b80957ddf629c454adee92b`。现有采集器记录每帧的 `t_unix`、`t_mono`、`tid`、加速度、角速度、欧拉角和四元数；`sample_us`、`ready_us` 在该会话没有出现。采集 CSV 的列顺序将四元数标为 `qw,qx,qy,qz`，欧拉角标为 `pitch,roll,yaw`；轴定义、旋转方向和欧拉角及角速度的单位没有独立实物验证。

20,052 帧对应 164 个不同主机接收时刻，每个时刻有 122–123 帧，批次间隔中位数 0.610084 s、最大 0.615829 s。四元数范数为 0.99999859–1.00000001；采用 `[w,x,y,z]` 并归一化后按 `2 acos(|q₁·q₂|)` 算出的相对旋转角，整段相对第一帧最大 84.089°，**同一接收批次首末帧的最大角差为 17.967°**。它是设备融合姿态的数值变化，不是独立参考测得的精度；归一化只用于计算，不改原数据。

这说明同批帧确实携带不同姿态值，但它们的设备采样时刻没有记录。同一主机时刻只选择批次末帧供画面示意时，会丢失批内变化，不能宣称该帧就是该主机时刻的物理姿态。可视化应保留批次首末帧、帧序、接收时刻、雷达包对应的主机时差，清楚标注代表帧和接收批次；不能以标称频率或批内线性插值暗示真实采样时间。

## 为什么不输出 IMU 位置轨迹

设备融合姿态可以展示为角度或姿态随**接收时间**的变化，但不能将姿态角当成位置轨迹。仅对加速度做二次积分会同时受未知采样时刻、初始速度、重力方向、偏置、轴向、单位和安装外参影响；本会话缺少这些量的独立约束，因此不输出貌似精确的位移或轨迹。

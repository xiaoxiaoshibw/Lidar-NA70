# 2026-11-11 Jetson NA70 实时点云现场记录

## 环境与连接

- 设备为 Jetson Orin Nano，SSH 管理地址 `jetson@192.168.31.168`；有线网口 `enP8p1s0` 通过交换机接收雷达，不要求通过有线上网。
- 历史网络契约和本次抓包显示雷达以 UDP `192.168.1.66:7000 → 192.168.1.129:2368` 发流，载荷 1410 字节。
- 独立实时页面部署在 Jetson `~/na70-live-web`，源码为 `tools/na70_live_web/`，转换使用项目 `na70_core.geometry`。HTTP 仅监听 `127.0.0.1:8795`，本机经 SSH 端口转发访问。服务未设为开机自启，运行时独占 UDP 2368。

## 真实录制

- 录制方式：Jetson 上 `sudo timeout -s INT 30 tcpdump -i enP8p1s0 -s 0 -U -w <文件> udp port 2368`。文件 `~/na70-live-recordings/na70-20261111-153914.pcap`，约 42 MiB，SHA-256 `72957ca999bedfcbe28ef2b4b39af1f2148d5590c0664d38e6cea67332ee0b05`。
- tcpdump 报告写入 29,913 包、过滤器收到 29,964 包、内核丢包 0；停止时两项计数相差 51，不能证明全链路零丢包。
- 对该文件检查得到 5,982,600 条射线，其中仅 9 条距离码非零。此录制时段回波极少；后续在页面出现的较多回波不在这段文件中。

## 实时观察与叠加

- 每连续接收 100 个有效长度数据包构成显示帧，并过滤零距离码；显示帧边界是接收端分组，不证明与设备完整扫描边界一致。
- 服务最多保留 30 帧，页面可选 1、5、10、20、30 帧，默认 10 帧；中断超过 1 秒并重新收包时清除旧帧。页面显示叠加点数、缓存帧数和最新帧点数。
- 录制之后现场实时回波恢复：一次页面检查显示 2,117 个有效点，浏览器截图中可见点云；一次实际帧数据的点距约 7.504–12.512 m。
- Chrome 自动化在不同时间采样验证选项：10 帧显示 6,050 点，1 帧显示 1,067 点，30 帧显示 21,120 点；不同采样时刻的点数不可直接用于定量对比覆盖率。超过 30 帧的 API 请求返回 HTTP 400。
- 记录时的一次状态查询显示最后数据包约 14.5 秒前到达；服务仍可访问，但该时刻数据未持续到达，需在现场重新确认设备和连线。

## 限制

叠加没有进行运动补偿、时间同步或配准，雷达或场景运动会产生重影；实时服务没有内核丢包统计。该结果只是实际收包、显示和交互的功能检查，不是识别、标定、SLAM、细线检测或性能验收；W1 归属仍为 `NOT_EVALUATED`，相关阶段状态不变。
